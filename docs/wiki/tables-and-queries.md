# Tables and Queries

## Decision

`Resource.make({ name, schema, authorization, storage?, relations?, operations })` is the generated persistence and routine-RPC interface. Its one `operations` record both selects publication and configures create/list behavior; legacy top-level `create` and `list` do not exist. `Table.make({ name, schema, relations? })` is the lower-level compiler. Authored SQL uses Effect `SqlSchema` and native `SqlClient`; other authored Effects use explicit schema conversions where needed. The 2026-09-08 user-approved simplification removes the earlier `Query.make` descriptor rather than preserving a compatibility wrapper. ([Resource](../../packages/effect-domains/src/resource.ts); [Table](../../packages/effect-domains/src/table.ts); [Authored SQL](../../apps/authored-sql/sqlite.ts); [superseded query direction](raw/table-and-query-api-direction.md))

Table names are application configuration; intrinsic identity belongs to the canonical schema through `identifier`. Without one, persistence adds a generated UUIDv7 `id` to its row representation. This cleanly supersedes older interfaces without a compatibility path. ([Domain identity direction](raw/domain-identifier-and-basic-persistence-direction.md); [Clean-cutover direction](raw/refactoring-and-compatibility-direction.md))

## Canonical and Storage Representations

`schema` is the canonical application representation. `storage`, when supplied, is a reversible persistence codec whose decoded fields must exactly match the canonical schema; storage therefore may use runtime dependencies without changing RPC wire contracts. `Table.make` derives physical SQLite fields, `insertSchema`, `rowSchema`, and `storageSchema` from that storage representation. ([Resource](../../packages/effect-domains/src/resource.ts); [Table](../../packages/effect-domains/src/table.ts); [service-codec example](../../apps/service-codec/storage.ts))

Table fields are compiled once and reused for physical metadata and codecs. `Table`, `Resource`, and `Application` are typed runtime descriptors, not `Schema.Class` values with opaque fields. Inspection encodes the native `Table.snapshot` as JSON rather than duplicating its physical DTO; physical field generation retains its native `generation` key. There is no runtime opaque placeholder object: compiler-local AST wrappers, storage entries, migration plans, repository requests, and authorization environments are readonly records, while handler services and transaction boundaries are deliberately not inspectable. Canonical models, external cursors, policy syntax, physical snapshots, and migration artifacts retain schema-backed contracts. Shared implicit-identifier augmentation preserves root struct checks for both Table and Resource; update and patch share their transactional persistence sequence without sharing action policy. ([Table compiler](../../packages/effect-domains/src/table.ts); [Inspection](../../packages/effect-domains/src/application-inspect.ts); [Resource](../../packages/effect-domains/src/resource.ts); [store boundary](../../packages/effect-domains/src/repository-store.ts); [root-check regressions](../../test/ResourceCrud.test.ts))

The current compiler supports flat required string, numeric, boolean, nullable scalar, and timestamp fields. Encoded names become columns; recognized checks become SQLite constraints. Arbitrary predicates and root checks remain schema validation, and nested rows, optional keys, bare `Option`, ambiguous identity, and non-scalar storage codecs are not claimed to work. ([Table](../../packages/effect-domains/src/table.ts); [SQLite DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [table regressions](../../test/Table.test.ts))

JavaScript string-length checks remain canonical validation rather than SQLite `length` constraints: UTF-16 code units, Unicode code points, and NUL handling are not equivalent. Historical artifacts retain their original DDL; explicit migrations remove the old constraints from current example databases. ([Compiler](../../packages/effect-domains/src/table.ts); [DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [Unicode persistence regression](../../test/Table.test.ts))

## Relational Storage Declarations

Optional `relations` declares named `unique`, `foreignKeys`, and `indexes` arrays on Table or Resource. Each entry has `name` and ordered `fields`; a foreign key additionally has `references: { table, fields }`. Local fields are typed, including a persistence-generated `id` where present. These are storage declarations, not inferred relationships from branded domain values. ([Table](../../packages/effect-domains/src/table.ts); [type boundaries](../../test/TableRelations.types.ts); [billing resources](../../apps/orders-invoices/resources.ts))

Table construction validates local fields and names. `Application.make` and migration snapshot validation check the complete managed graph: target tables and columns, tuple arity, physical scalar compatibility, and a referenced primary key or declared unique tuple. Index names occupy SQLite's database-wide namespace. Construction snapshots declarations; omitted relational metadata remains absent from historical snapshot JSON. Primary identity remains a single field, while uniqueness and foreign keys may be composite. ([Application](../../packages/effect-domains/src/application.ts); [Table](../../packages/effect-domains/src/table.ts); [migrations](../../packages/effect-domains/src/sqlite-migrations.ts))

SQLite derives named table constraints and separate index statements. Foreign keys are enabled on the runtime connection and use SQLite's default `NO ACTION`; no cascade, join, eager loading, or aggregate transaction is inferred. The billing slice declares `(tenantId, orderId) → orders(tenantId, id)` to prevent cross-tenant references even in privileged SQL. Its joins, role checks, checked minor-unit arithmetic, and compare-and-swap transitions are authored with native `SqlSchema` and `SqlClient`. ([DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [runtime](../../packages/effect-domains/src/sqlite-bun.ts); [billing SQL](../../apps/orders-invoices/sqlite.ts))

## Generated Resource Operations

`Resource.crud` is the frozen `{ get: true, list: true, create: true, update: true, remove: true }` operation record. `operations` is an object record, not an array: `true` selects default behavior, `false` and omission do not publish that RPC, `patch: true` selects patch, and `operations: {}` publishes none. Repositories retain every method for authored local use regardless of publication. ([Resource](../../packages/effect-domains/src/resource.ts); [reservation resources](../../apps/reservations/resources.ts))

The minimal book application selects `operations: Resource.crud` and has no authored contracts or handlers. The separate authored-SQL application shares its canonical `BookSchema` but intentionally declares different errors and a remove result containing the deleted row. Generated remove returns `void`; those semantic differences are not inferred. ([Basic resource](../../apps/basic-crud/resources.ts); [Canonical book](../../packages/example-support/src/book.ts); [Authored contracts](../../apps/authored-sql/contracts.ts))

`operations.create` contains creation policy: `defaults` fills a field only when omitted; `generated` fields are produced by the runtime `Value` service from `uuidV7` or `now` tokens; and, for policy-authorized resources, `fromSubject` maps a target field to a typed `p.subject` operand. Generated and subject-bound fields are neither TypeScript nor wire create input, supplied values are rejected, and bindings cannot overlap defaults or generation. An implicit persistence identifier is generated in the same manner. ([Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts); [Value](../../packages/effect-domains/src/value.ts))

Subject-binding compatibility is directional: a required subject field can populate a nullable destination, but a nullable source cannot populate a required destination. Runtime construction and TypeScript enforce the same direction. ([Authorization](../../packages/effect-domains/src/authorization.ts); [runtime regression](../../test/Authorization.test.ts); [type regression](../../test/Authorization.types.ts))

`operations.list`, for example `{ filter: ["completed"], order: [{ field: "title" }], limit: 50 }`, exposes only those filters and order, with the identifier as a stable tie-breaker. Its response is `{ items, nextCursor }`; cursors bind the resource, filter, order, scalar values, and identifier. Native CLI flags support paths such as `--filter-completed` and `--changes-title`, alongside `--input-json`. ([Resource](../../packages/effect-domains/src/resource.ts); [CLI](../../packages/effect-domains/src/rpc-cli.ts); [resource regressions](../../test/ResourceCrud.test.ts))

Published patch input is `{ key, changes }`, regardless of the canonical identifier's name; the repository remains `patch(key, changes)`. Identifier fields cannot occur in `changes`, while ordinary canonical fields named `key`, `changes`, or `patch` cannot collide with the envelope. The merged canonical value is validated before writing, so invalid patches leave storage unchanged. ([Resource](../../packages/effect-domains/src/resource.ts); [runtime regressions](../../test/ResourceCrud.test.ts); [type regressions](../../test/ResourceCrud.types.ts))

## Resource Authorization

Every resource selects `Authorization.public`, `Authorization.deny`, or `Authorization.for({ resource, subject }).policy({ scope, allow })`. Typed `row`, `next`, and `subject` references compose equality, membership, conjunction, disjunction, and unchanged-field policies; phase typing rejects current-state references in create and candidate-state references in read. Omitted actions deny. Policy is authored resource configuration, not inferred domain metadata. ([Authorization](../../packages/effect-domains/src/authorization.ts); [type boundaries](../../test/Authorization.types.ts))

Policy construction validates, snapshots, and freezes syntax once, retaining compiled evaluators in private instance state. Fabricated policy descriptors are rejected. Resource binding still checks canonical identity, storage compatibility, and subject bindings; invocation still resolves and validates current authenticated claims. Runtime and SQL interpreters share literal/subject operand resolution, while SQL row identifiers, candidate-phase restrictions, and runtime short-circuiting remain separate. ([Authorization](../../packages/effect-domains/src/authorization.ts); [Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [lifetime regressions](../../test/Authorization.test.ts))

The closed schema-backed `Policy` AST and `PolicyF` fold drive Effect evaluation, parameterized SQL, field references, and rendered inspection. Equality is total over finite scalar values without coercion. SQL visibility accepts identity-compatible string/numeric storage fields, optionally nullable, and native Boolean fields through their SQLite numeric `0`/`1` encoding. Arbitrary semantic Boolean codecs remain rejected for visibility rather than approximated. Standalone evaluation can use Boolean policies. ([Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [parity regressions](../../test/Policy.test.ts))

`scope` always constrains visibility and current/candidate state. Hidden rows look missing, and list filtering occurs before SQL pagination. Mutations authorize complete candidates, require readable create/update/patch results, and check persisted returned rows. Checks and writes are transactional; repositories do not bypass policy when called from authored Effects. Native `SqlClient` and `RepositoryStore` remain privileged escape hatches. ([Resource](../../packages/effect-domains/src/resource.ts); [SQLite](../../packages/effect-domains/src/sqlite-bun.ts); [authorization regressions](../../test/Authorization.test.ts))

Protected generated RPCs authenticate per request through `AuthorizationRpc.Authenticator`, whose `authenticate(headers)` supplies verified `AuthorizationSubject` claims or fails with `Unauthenticated`. Missing authenticators and forged identity headers cannot fall back to a captured subject. The CLI sends `<APP>_TOKEN` as a bearer token; verification and issuance remain application responsibilities. Authored Effects may supply trusted subjects and use `Authorization.require` with `AuthorizationValues.make({ row, next })`, where row and candidate values are `Option`s. ([RPC authentication](../../packages/effect-domains/src/authorization-rpc.ts); [authorization](../../packages/effect-domains/src/authorization.ts); [identity-isolation regressions](../../test/AuthorizationRpc.test.ts))

## Commands, Applications, and Admin

Authored applications declare native `Rpc.make` and `RpcGroup.make` contracts and register `{ group, handlers: group.toLayer(...) }` bundles. JSON-native schemas can be used directly; non-JSON-native representations such as reservation timestamps use explicit `Schema.toCodecJson`. There is no framework command-service constructor, handler-type system, or context-capture wrapper. ([Book contracts](../../apps/authored-sql/contracts.ts); [reservation contracts](../../apps/reservations/contracts.ts); [billing composition](../../apps/orders-invoices/application.ts))

SQL and repository failure translation belongs to authored `Effect.catchTags` after transactions unwind. Business errors remain declared by native RPC schemas; native handler types enforce those outcomes. Local tests use native RPC clients rather than an injectable command service. Middleware supplies request-local subjects through RPC dispatch, and each invocation closes its handler scope without ending an MCP session. Native `accessHandler` is not an authentication boundary. ([Reservation handlers](../../apps/reservations/sqlite.ts); [billing handlers](../../apps/orders-invoices/sqlite.ts); [MCP scope and identity regressions](../../test/RpcMcp.test.ts); [removal evidence](validation-strategy.md#2026-09-09-command-wrapper-removal))

`Application.make({ name, parts })` joins Resources, native `{ group, handlers }` bundles, and nested Applications. Nested resource lists flatten into the composed application; construction rejects duplicate resource table names and duplicate RPC operation names. There is no `Commands.make`, `rpc` wrapper, or compatibility adapter. `ApplicationBun.run(application, options)` returns an `Effect` for native `BunRuntime.runMain`. Its database option is `{ manifest: string | URL, filename?: string }` or `{ migrations, filename?: string }`. Startup validates database separation, prepares application SQLite history, builds optional private execution services, builds application services, runs initialization, registers background layers, and starts HTTP or a worker lifetime in the same scope. `schema` and `inspect` do not start these background runtimes or build browser assets. ([Application](../../packages/effect-domains/src/application.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

CLI, MCP, admin, and inspection use one private unary-RPC contract compiler for canonical JSON codecs and the union of declared and middleware errors. Transport-specific envelopes, CLI flags, HTTP statuses, and authentication remain adapter concerns. Inspection therefore includes authentication middleware failures even when an RPC declares no errors itself. ([Shared compiler](../../packages/effect-domains/src/rpc-contract.ts); [inspection regression](../../test/ApplicationAdmin.test.ts))

Absent CLI input is derived from the operation schema: no-payload RPCs encode/decode their void representation, while empty structs receive `{}`. Explicit JSON and native-field conflict checks remain unchanged. ([CLI](../../packages/effect-domains/src/rpc-cli.ts); [live CLI regressions](../../test/RpcCli.test.ts))

The same `serve` runtime mounts Effect RPC at `/rpc/v1` and derived MCP tools at `/mcp`. Its opt-in `admin: true | { path?, presentation?, allowedOrigins? }` additionally serves a generated browser interface at `/admin` by default. [`apps/admin`](../../apps/admin/) is built explicitly with `bun install` then `bun run build`; when admin is enabled, the Bun adapter loads only its prebuilt `dist/client.js` and `dist/style.css` assets. `ApplicationAdmin.layerHttp({ application, javascript, stylesheet, path?, presentation?, allowedOrigins? })` is the lower-level adapter. Admin and MCP invoke the same in-process RPC transport, preserving handlers, middleware, service-dependent codecs, and per-call bearer authentication without persisting a token. ([Browser client](../../apps/admin/src/client.ts); [Browser stylesheet](../../apps/admin/src/style.css); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [in-process RPC](../../packages/effect-domains/src/rpc-in-process.ts); [MCP adapter](../../packages/effect-domains/src/rpc-mcp.ts))

One handler defect does not terminate unrelated requests sharing the in-process transport. Payload decoding and success/error encoding use the RPC handler's captured service context, not an ambient adapter override; request dispatch remains outside that codec context so per-call authentication is preserved. ([In-process transport](../../packages/effect-domains/src/rpc-in-process.ts); [admin regressions](../../test/ApplicationAdmin.test.ts); [MCP regressions](../../test/RpcMcp.test.ts))

The admin uses inspection to generate operation forms, resource lists, declared filters, cursor paging, and a complete-JSON fallback. It presents optional application-supplied titles, labels, columns, and descriptions, none of which becomes canonical resource or operation metadata. Server-side schemas and authorization remain authoritative; the interface infers no permissions. Its browser API accepts same-origin calls and trusts loopback hosts by default. A non-loopback host must name exact `allowedOrigins`; this is an origin check, not a CORS grant. ([Admin client](../../apps/admin/src/client.ts); [Admin stylesheet](../../apps/admin/src/style.css); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Inspection](../../packages/effect-domains/src/application-inspect.ts))

## Native Durable Execution

Application `parts` accept native `{ group, handlers }` bundles. `WorkflowProxy.toRpcGroup` / `WorkflowProxyServer.layerRpcHandlers` and `EntityProxy.toRpcGroup` / `EntityProxyServer.layerRpcHandlers` therefore compose directly; there is no second workflow, job, or actor contract. Native unary procedures retain generated CLI, MCP, and inspection support. Authenticate and authorize the published proxy group explicitly, including submission, resume, and polling: persisted execution is not an authenticated HTTP request, and inner protocol annotations do not automatically protect a proxy boundary. ([Workflow commands](../../apps/durable-workflows/contracts.ts); [entity proxy](../../apps/durable-reminders/reminder-entity.ts); [proxy regression](../../test/WorkflowApplication.test.ts))

`execution: { database: string | URL, layer }` builds native SQL-backed execution services against a private SQLite connection. The runner removes the private SQL service tags from the resulting application context. It rejects application/execution filename aliases before opening either database, including existing symlinks and hardlinks; dangling symlinks and ambiguous SQLite URI filenames are rejected. This is a startup guard, not protection against concurrent filesystem replacement. Framework resource history manages only the application database; native Effect services own their execution tables and migrations. ([Runtime](../../packages/effect-domains/src/application-bun.ts); [database-isolation regressions](../../test/ApplicationExecution.test.ts))

`background` accepts a native `Layer` for workflow registrations, queue consumers, entity registrations, singletons, or cron tasks. It starts after application services and initialization under both `serve` and the conditionally available `worker` command. `worker` opens no HTTP listener. `routes` accepts native `HttpRouter` layers for `serve`, with application handler and runtime services available to requests. Neither option changes canonical schemas or derives business policy. ([Runtime](../../packages/effect-domains/src/application-bun.ts); [runtime requirement checks](../../test/Application.types.ts); [workflow composition](../../apps/durable-workflows/runtime.ts))

Native Sharding supplies its own private `SqlClient` during Entity and ClusterCron execution. Code that needs application SQL must capture the application connection in its registration layer, or provide a narrow application store whose methods close over that connection. Merely omitting private SQL from the outer execution output does not override native invocation context. The reminder registrations explicitly capture application SQL before constructing handlers and retention work. ([Reminder background](../../apps/durable-reminders/background.ts))

The workflow application reads native `Sharding` and `RunnerStorage` services for runner health, active-entity count, and shutdown state. Its private response schemas and authenticated `DurableWorkflow.Status` command are application-owned; the framework has no cluster-diagnostics wrapper. The example separately authenticates `/operator/metrics` before formatting native Prometheus metrics. Keep diagnostics exposure and authorization explicit. ([Status command](../../apps/durable-workflows/workflow.ts); [metrics route](../../apps/durable-workflows/routes.ts))

The examples use native `SingleRunner`; run either `serve` or `worker` against a given execution store, not both concurrently. The workflow combines durable sleep, approval, activities, and a SQL-backed `DurableQueue` whose completion resumes the workflow. The reminder uses persisted per-recipient messages with `PrimaryKey` and `DeliverAt`, an idempotent receipt transaction, a singleton file projection, and explicit UTC retention scheduling. Application and execution transactions are separate: no automatic outbox, cross-database transaction, or exactly-once external effect is implied. ([Workflow](../../apps/durable-workflows/workflow.ts); [artifact writer](../../apps/durable-workflows/writer.ts); [reminder background](../../apps/durable-reminders/background.ts); [runbooks](../../apps/README.md#durable-workflows))

## Authored Queries

Effect `SqlSchema.findOne`, `findOneOption`, and `findAll` encode requests and decode SQL results while retaining codec-service dependencies. Authored effects use the same native `SqlClient` supplied to generated repositories, so their transaction boundaries compose. Explicit schema encode/decode remains available when upstream SQL cardinality semantics do not fit. ([Authored book queries](../../apps/authored-sql/sqlite.ts); [SQLite integration](../../test/SqliteBun.test.ts); [runtime](../../packages/effect-domains/src/sqlite-bun.ts))

Generated repositories and authored SQL operate on persisted state without a framework-owned cache. Applications needing cached state must explicitly own invalidation and concurrency policy; a process-local synchronized value cannot provide database-wide conflict detection. ([Authored book queries](../../apps/authored-sql/sqlite.ts); [transactional reservation policy](../../apps/reservations/sqlite.ts))

## SQLite Migrations and Inspection

`SqliteMigrations.decodeHistory(raw)` decodes and validates fixture history as an Effect. Production startup can receive `{ migrations: decodedHistory, filename?: string }`, or `{ manifest: string | URL, filename?: string }`; `SqliteMigrations.load` reads ordered manifest artifacts. Fresh schemas are generated through `schema generate <name>` against an explicit manifest. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

Each table-bearing example resolves its manifest to an absolute path in `main.ts` and calls `ApplicationBun.run`. The workflow-only example has no application tables and supplies empty history. Static history modules remain where regression setup or historical seed code consumes them. ([Workflow entrypoint](../../apps/durable-workflows/main.ts); [billing fixture](../../apps/orders-invoices/migrations.ts); [Reservation fixture](../../apps/reservations/migrations.ts); [Document seed](../../apps/migration-lifecycle/seed-v1.ts))

Migration changes needing meaning require explicit `--rename`, `--backfill`, or `--transform` intent. The generator validates its artifact before writing it and atomically replaces the manifest only after success; blocked plans leave the registry unchanged. Every nonempty managed schema requires an initial migration. There is no direct table-write service, artifact-free bootstrap, or later adoption path: the applied-artifact ledger determines expected state. Runtime verifies actual schema and ledger contents and applies pending migrations transactionally. Empty schemas may use empty history. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

The schema CLI uses its manifest as the sole history authority. Each intent flag is repeatable and parsed into typed values before planning; embedded colons remain part of JSON values or SQL expressions. Each target field resolves to an existing column, explicit transform, explicit backfill, nullable addition, or blocked decision before direct/rebuild emission. Missing rename sources are blocked rather than becoming nullable additions. In-memory metadata comparison uses schema-derived equality, while ledger serialization remains canonical and frozen artifact formats remain unchanged. ([Planner and CLI](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

Rename chains and cycles are planned at table level and rebuilt from original source columns, avoiding sequential rename collisions. Nullable identifiers are rejected when loading snapshots or migration history. ([Planner](../../packages/effect-domains/src/sqlite-migrations.ts); [applied-row regressions](../../test/SqliteMigrations.test.ts))

The [todo](../../apps/resource-crud/migrations/003_schema_string_checks.json), [document](../../apps/migration-lifecycle/migrations/003_schema_string_checks.json), and [reservation](../../apps/reservations/migrations/003_schema_string_checks.json) histories append explicit identity-copy rebuilds removing misderived string-length constraints. Existing artifacts and the historical DDL renderer are unchanged.

Declared index changes emit explicit create/drop-index steps; unique and foreign-key changes rebuild tables. Replay defers foreign-key checks inside the migration transaction, verifies the final schema and `foreign_key_check`, clears SQLite's deferred-counter state, and records the artifact before commit. Invalid existing rows roll back the migration and ledger together. Exact declared index SQL is verified; untracked indexes and triggers remain drift. Historical artifacts without relational metadata retain their original serialization. ([Planner and replay](../../packages/effect-domains/src/sqlite-migrations.ts); [rollback, parent-rebuild, and index-drift regressions](../../test/RelationalMigrations.test.ts))

Relational declarations are exposed as `storage.physical.relations` in inspection. They describe storage structure, not query dependencies or transaction boundaries. ([Inspection](../../packages/effect-domains/src/application-inspect.ts))

`inspect` emits canonical resource schemas, authorization subject schemas and rendered scope/action policies, `operations.create` defaults/generation and `fromSubject` mappings, `operations.list` policy, canonical/storage/insert/row/stored representations, JSON-encoded native `Table.snapshot` physical metadata, and operation input/output/error schemas. It is input to the opt-in admin interface, but presentation configuration is not canonical metadata. It does not create opaque runtime metadata for handler services or transactions; those boundaries remain authored and uninspectable. ([Inspection](../../packages/effect-domains/src/application-inspect.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

## Evidence Boundary

Previously dated evidence covers one SQLite adapter, the reservation slice, six supporting applications, scoped document authorization, and authenticated todo/note examples. It does not establish another database, relationships, indexes, a production identity provider, retries, idempotency, distributed coherence, or a materially different business-policy domain, and does not itself validate later changes. ([Example verification](validation-strategy.md#2026-09-09-authorized-examples); [Authorization verification](validation-strategy.md#2026-09-08-resource-authorization); [Project thesis](raw/project-thesis.md))

The newer [durable-execution verification](validation-strategy.md#2026-09-09-native-durable-execution) establishes bounded restart recovery, idempotent replay of the demonstrated effects, and selective native scheduling composition. It does not establish multi-runner coordination, cross-database atomicity, arbitrary external-effect idempotency, or a general actor/job framework.

The [orders/invoices verification](validation-strategy.md#2026-09-09-tenant-scoped-orders-and-invoices) adds bounded evidence for composite relationships, declared indexes, tenant-scoped multi-resource commands, and database-guarded stale-write rejection in a second business domain. It does not establish another database, production identity, billing-provider integration, automatic joins, or general conflict-resolution policy.
