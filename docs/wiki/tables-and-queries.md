# Tables and Queries

## Decision

`Resource.make({ name, schema, authorization, storage?, operations, create?, list? })` is the generated persistence and routine-RPC interface. `Table.make({ name, schema })` is the lower-level compiler. Authored SQL uses Effect `SqlSchema` and native `SqlClient`; other authored Effects use explicit schema conversions where needed. The 2026-09-08 user-approved simplification removes the earlier `Query.make` descriptor rather than preserving a compatibility wrapper. ([Resource](../../packages/effect-domains/src/resource.ts); [Table](../../packages/effect-domains/src/table.ts); [Authored SQL](../../apps/authored-sql/sqlite.ts); [superseded query direction](raw/table-and-query-api-direction.md))

Table names are application configuration; intrinsic identity belongs to the canonical schema through `identifier`. Without one, persistence adds a generated UUIDv7 `id` to its row representation. This cleanly supersedes older interfaces without a compatibility path. ([Domain identity direction](raw/domain-identifier-and-basic-persistence-direction.md); [Clean-cutover direction](raw/refactoring-and-compatibility-direction.md))

## Canonical and Storage Representations

`schema` is the canonical application representation. `storage`, when supplied, is a reversible persistence codec whose decoded fields must exactly match the canonical schema; storage therefore may use runtime dependencies without changing RPC wire contracts. `Table.make` derives physical SQLite fields, `insertSchema`, `rowSchema`, and `storageSchema` from that storage representation. ([Resource](../../packages/effect-domains/src/resource.ts); [Table](../../packages/effect-domains/src/table.ts); [service-codec example](../../apps/service-codec/storage.ts))

Table fields are compiled once and reused for physical metadata and codecs. `Table`, `Resource`, and `Application` are typed runtime descriptors, not `Schema.Class` values with opaque fields; persisted snapshots remain real schemas. Table and CLI interpreters traverse the Effect AST directly with target-specific semantics. ([Table compiler](../../packages/effect-domains/src/table.ts); [CLI](../../packages/effect-domains/src/rpc-cli.ts); [Application](../../packages/effect-domains/src/application.ts))

Each compiled column exposes its physical storage codec and conservative ordering capability. Query filters use that codec, including automatically encoded timestamps; sharing a canonical/storage schema alone does not prove comparison semantics. Semantic codecs such as `NumberFromString` cannot supply inferred ordering. Suspended scalar wrappers retain Boolean/timestamp conversions, and nullable physical identifiers are rejected. ([Table](../../packages/effect-domains/src/table.ts); [query regressions](../../test/ResourceCrud.test.ts); [scalar regressions](../../test/Table.test.ts))

Compiler-local AST wrappers, storage entries, migration plans, repository requests, and authorization environments use readonly records rather than runtime schemas. Canonical models, external cursors, policy syntax, physical snapshots, and migration artifacts retain schema-backed contracts. Shared implicit-identifier augmentation preserves root struct checks for both Table and Resource; update and patch share their transactional persistence sequence without sharing action policy. ([Table](../../packages/effect-domains/src/table.ts); [Resource](../../packages/effect-domains/src/resource.ts); [store boundary](../../packages/effect-domains/src/repository-store.ts); [root-check regressions](../../test/ResourceCrud.test.ts))

The current compiler supports flat required string, numeric, boolean, nullable scalar, and timestamp fields. Encoded names become columns; recognized checks become SQLite constraints. Arbitrary predicates and root checks remain schema validation, and nested rows, optional keys, bare `Option`, ambiguous identity, and non-scalar storage codecs are not claimed to work. ([Table](../../packages/effect-domains/src/table.ts); [SQLite DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [table regressions](../../test/Table.test.ts))

JavaScript string-length checks remain canonical validation rather than SQLite `length` constraints: UTF-16 code units, Unicode code points, and NUL handling are not equivalent. Historical artifacts retain their original DDL; explicit migrations remove the old constraints from current example databases. ([Compiler](../../packages/effect-domains/src/table.ts); [DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [Unicode persistence regression](../../test/Table.test.ts))

## Generated Resource Operations

`Resource.crud` is the existing `get`, `list`, `create`, `update`, and `remove` tuple. A resource publishes only operations named in `operations`; adding `patch` is explicit. Repositories remain available to authored code regardless of what was published. ([Resource](../../packages/effect-domains/src/resource.ts); [reservation resources](../../apps/reservations/resources.ts))

The minimal book application selects `Resource.crud` and has no authored contracts or handlers. The separate authored-SQL application shares its canonical `BookSchema` but intentionally declares different errors and a remove result containing the deleted row. Generated remove returns `void`; those semantic differences are not inferred. ([Basic resource](../../apps/basic-crud/resources.ts); [Canonical book](../../packages/example-support/src/book.ts); [Authored contracts](../../apps/authored-sql/contracts.ts))

Creation policy has three deliberate cases: `defaults` fills a field only when omitted; `generated` fields are produced by the runtime `Value` service from `uuidV7` or `now` tokens; and, for policy-authorized resources, `fromSubject` maps a target field to a typed `p.subject` operand. Generated and subject-bound fields are neither TypeScript nor wire create input, supplied values are rejected, and bindings cannot overlap defaults or generation. An implicit persistence identifier is generated in the same manner. ([Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts); [Value](../../packages/effect-domains/src/value.ts))

Subject-binding compatibility is directional: a required subject field can populate a nullable destination, but a nullable source cannot populate a required destination. Runtime construction and TypeScript enforce the same direction. ([Authorization](../../packages/effect-domains/src/authorization.ts); [runtime regression](../../test/Authorization.test.ts); [type regression](../../test/Authorization.types.ts))

A `list` declaration, for example `{ filter: ["completed"], order: [{ field: "title" }], limit: 50 }`, exposes only those filters and order, with the identifier as a stable tie-breaker. Its response is `{ items, nextCursor }`; cursors bind the resource, filter, order, scalar values, and identifier. Native CLI flags support paths such as `--filter-completed` and `--changes-title`, alongside `--input-json`. ([Resource](../../packages/effect-domains/src/resource.ts); [CLI](../../packages/effect-domains/src/rpc-cli.ts); [resource regressions](../../test/ResourceCrud.test.ts))

Published patch input is `{ key, changes }`, regardless of the canonical identifier's name; the repository remains `patch(key, changes)`. Identifier fields cannot occur in `changes`, while ordinary canonical fields named `key`, `changes`, or `patch` cannot collide with the envelope. The merged canonical value is validated before writing, so invalid patches leave storage unchanged. ([Resource](../../packages/effect-domains/src/resource.ts); [runtime regressions](../../test/ResourceCrud.test.ts); [type regressions](../../test/ResourceCrud.types.ts))

## Resource Authorization

Every resource selects `Authorization.public`, `Authorization.deny`, or `Authorization.for({ resource, subject }).policy({ scope, allow })`. Typed `row`, `next`, and `subject` references compose equality, membership, conjunction, disjunction, and unchanged-field policies; phase typing rejects current-state references in create and candidate-state references in read. Omitted actions deny. Policy is authored resource configuration, not inferred domain metadata. ([Authorization](../../packages/effect-domains/src/authorization.ts); [type boundaries](../../test/Authorization.types.ts))

Policy construction validates and snapshots immutable syntax and retains compiled evaluators in a private identity registry. Fabricated policy descriptors are rejected. Resource binding still checks canonical identity, storage compatibility, and subject bindings; invocation still resolves and validates current authenticated claims. Runtime and SQL interpreters share literal/subject operand resolution, while SQL row identifiers, candidate-phase restrictions, and runtime short-circuiting remain separate. ([Authorization](../../packages/effect-domains/src/authorization.ts); [Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [lifetime regressions](../../test/Authorization.test.ts))

The closed schema-backed `Policy` AST and `PolicyF` fold drive Effect evaluation, parameterized SQL, field references, and rendered inspection. Equality is total over finite scalar values without coercion. SQL visibility accepts identity-compatible string/numeric storage fields, optionally nullable, and native Boolean fields through their SQLite numeric `0`/`1` encoding. Arbitrary semantic Boolean codecs remain rejected for visibility rather than approximated. Standalone evaluation can use Boolean policies. ([Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [parity regressions](../../test/Policy.test.ts))

`scope` always constrains visibility and current/candidate state. Hidden rows look missing, and list filtering occurs before SQL pagination. Mutations authorize complete candidates, require readable create/update/patch results, and check persisted returned rows. Checks and writes are transactional; repositories do not bypass policy when called from authored Effects. Native `SqlClient` and `RepositoryStore` remain privileged escape hatches. ([Resource](../../packages/effect-domains/src/resource.ts); [SQLite](../../packages/effect-domains/src/sqlite-bun.ts); [authorization regressions](../../test/Authorization.test.ts))

Protected generated RPCs authenticate per request through `AuthorizationRpc.Authenticator`, whose `authenticate(headers)` supplies verified `AuthorizationSubject` claims or fails with `Unauthenticated`. Missing authenticators and forged identity headers cannot fall back to a captured subject. The CLI sends `<APP>_TOKEN` as a bearer token; verification and issuance remain application responsibilities. Authored Effects may supply trusted subjects and use `Authorization.require` with `AuthorizationValues.make({ row, next })`, where row and candidate values are `Option`s. ([RPC authentication](../../packages/effect-domains/src/authorization-rpc.ts); [authorization](../../packages/effect-domains/src/authorization.ts); [identity-isolation regressions](../../test/AuthorizationRpc.test.ts))

## Commands, Applications, and Admin

`Commands.make({ name, group })` wraps a native Effect `RpcGroup` in an injectable service descriptor and `.layer`, accepting a unary handler record or Effect. The group is retained, not regenerated from a second contract format. `Commands.rpc(tag, { payload, success, error })` derives JSON codecs; native `Rpc.make` remains the escape hatch. Local service methods receive decoded payloads; invocation context overrides captured fallback dependencies. `.layer(handlers, catchTags)` accepts an optional direct mapper record and maps only matching tagged invocation errors after authored transactions unwind. Acquisition failures, defects, interruption, and unmatched errors remain unchanged; mapped results must satisfy the RPC declaration. ([Commands](../../packages/effect-domains/src/commands.ts); [Book RPCs](../../apps/authored-sql/contracts.ts))

Direct command methods retain the services normally provided by RPC middleware and close each invocation's scope before returning. Optional mapper entries contribute possible success and failure outcomes to validation; only guaranteed mapper keys remove an original tagged error from the contract. ([Commands](../../packages/effect-domains/src/commands.ts); [scope/context regressions](../../test/Commands.test.ts); [mapper type regressions](../../test/Commands.types.ts))

`Application.make({ name, resources?, commands? })` joins descriptor/resource groups and handler layers; either group may be omitted. `ApplicationBun.run(application, options)` returns an `Effect`; entrypoints execute it with native `BunRuntime.runMain`. The required database option is either `{ manifest: string | URL, filename?: string }` or `{ migrations, filename?: string }`; services and initialization are optional. Startup builds SQLite, prepares tables, builds services, runs initialization, then starts HTTP serving. `schema` and `inspect` never build the browser application. ([Application](../../packages/effect-domains/src/application.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [entrypoint](../../apps/basic-crud/main.ts))

CLI, MCP, admin, and inspection use one private unary-RPC contract compiler for canonical JSON codecs and the union of declared and middleware errors. Transport-specific envelopes, CLI flags, HTTP statuses, and authentication remain adapter concerns. Inspection therefore includes authentication middleware failures even when an RPC declares no errors itself. ([Shared compiler](../../packages/effect-domains/src/rpc-contract.ts); [inspection regression](../../test/ApplicationAdmin.test.ts))

Absent CLI input is derived from the operation schema: no-payload RPCs encode/decode their void representation, while empty structs receive `{}`. Explicit JSON and native-field conflict checks remain unchanged. ([CLI](../../packages/effect-domains/src/rpc-cli.ts); [live CLI regressions](../../test/RpcCli.test.ts))

The same `serve` runtime mounts Effect RPC at `/rpc/v1` and derived MCP tools at `/mcp`. Its opt-in `admin: true | { path?, presentation?, allowedOrigins? }` additionally serves a generated browser interface at `/admin` by default. [`apps/admin`](../../apps/admin/) is built explicitly with `bun install` then `bun run build`; when admin is enabled, the Bun adapter loads only its prebuilt `dist/client.js` and `dist/style.css` assets. `ApplicationAdmin.layerHttp({ application, javascript, stylesheet, path?, presentation?, allowedOrigins? })` is the lower-level adapter. Admin and MCP invoke the same in-process RPC transport, preserving handlers, middleware, service-dependent codecs, and per-call bearer authentication without persisting a token. ([Browser client](../../apps/admin/src/client.ts); [Browser stylesheet](../../apps/admin/src/style.css); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [in-process RPC](../../packages/effect-domains/src/rpc-in-process.ts); [MCP adapter](../../packages/effect-domains/src/rpc-mcp.ts))

One handler defect does not terminate unrelated requests sharing the in-process transport. Payload decoding and success/error encoding use the RPC handler's captured service context, not an ambient adapter override; request dispatch remains outside that codec context so per-call authentication is preserved. ([In-process transport](../../packages/effect-domains/src/rpc-in-process.ts); [admin regressions](../../test/ApplicationAdmin.test.ts); [MCP regressions](../../test/RpcMcp.test.ts))

The admin uses inspection to generate operation forms, resource lists, declared filters, cursor paging, and a complete-JSON fallback. It presents optional application-supplied titles, labels, columns, and descriptions, none of which becomes canonical resource or operation metadata. Server-side schemas and authorization remain authoritative; the interface infers no permissions. Its browser API accepts same-origin calls and trusts loopback hosts by default. A non-loopback host must name exact `allowedOrigins`; this is an origin check, not a CORS grant. ([Admin client](../../apps/admin/src/client.ts); [Admin stylesheet](../../apps/admin/src/style.css); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Inspection](../../packages/effect-domains/src/application-inspect.ts))

## Authored Queries and Persisted References

Effect `SqlSchema.findOne`, `findOneOption`, and `findAll` encode requests and decode SQL results while retaining codec-service dependencies. Authored effects use the same native `SqlClient` supplied to generated repositories, so their transaction boundaries compose. Explicit schema encode/decode remains available when upstream SQL cardinality semantics do not fit. ([Authored book queries](../../apps/authored-sql/sqlite.ts); [SQLite integration](../../test/SqliteBun.test.ts); [runtime](../../packages/effect-domains/src/sqlite-bun.ts))

`PersistedRef.fromResource(resource, { key, ifMissing })` performs missing-row initialization in the repository transaction, preserves the bound key for commits, and reports a deleted row on refresh instead of recreating it. The resource's derived `createInputSchema` validates already-decoded creation input; omitted defaults and generated values remain the repository's responsibility. It serializes only in-process mutations; explicit refresh is not a distributed-coherence or conflict-resolution mechanism. ([PersistedRef](../../packages/effect-domains/src/persisted-ref.ts); [persisted-resource regression](../../test/PersistedResource.test.ts))

## SQLite Migrations and Inspection

`SqliteMigrations.decodeHistory(raw)` decodes and validates fixture history as an Effect. Production startup can receive `{ migrations: decodedHistory, filename?: string }`, or `{ manifest: string | URL, filename?: string }`; `SqliteMigrations.load` reads ordered manifest artifacts. Fresh schemas are generated through `schema generate <name>` against an explicit manifest. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

Every runnable example resolves its own manifest to an absolute path in `main.ts` and calls `ApplicationBun.run`. Static history modules remain only for the reservation regression and historical document seed; unused duplicate registries are removed. ([Reservation fixture](../../apps/reservations/migrations.ts); [Document seed](../../apps/migration-lifecycle/seed-v1.ts))

Migration changes needing meaning require explicit `--rename`, `--backfill`, or `--transform` intent. The generator validates its artifact before writing it and atomically replaces the manifest only after success; blocked plans leave the registry unchanged. Every nonempty managed schema requires an initial migration. There is no direct table-write service, artifact-free bootstrap, or later adoption path: the applied-artifact ledger determines expected state. Runtime verifies actual schema and ledger contents and applies pending migrations transactionally. Empty schemas may use empty history. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

The schema CLI uses its manifest as the sole history authority. Each intent flag is repeatable and parsed into typed values before planning; embedded colons remain part of JSON values or SQL expressions. Each target field resolves to an existing column, explicit transform, explicit backfill, nullable addition, or blocked decision before direct/rebuild emission. Missing rename sources are blocked rather than becoming nullable additions. In-memory metadata comparison uses schema-derived equality, while ledger serialization remains canonical and frozen artifact formats remain unchanged. ([Planner and CLI](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

Rename chains and cycles are planned at table level and rebuilt from original source columns, avoiding sequential rename collisions. Nullable identifiers are rejected when loading snapshots or migration history. ([Planner](../../packages/effect-domains/src/sqlite-migrations.ts); [applied-row regressions](../../test/SqliteMigrations.test.ts))

The [todo](../../apps/resource-crud/migrations/003_schema_string_checks.json), [document](../../apps/migration-lifecycle/migrations/003_schema_string_checks.json), and [reservation](../../apps/reservations/migrations/003_schema_string_checks.json) histories append explicit identity-copy rebuilds removing misderived string-length constraints. Existing artifacts and the historical DDL renderer are unchanged.

`inspect` emits canonical resource schemas, authorization subject schemas and rendered scope/action policies, creation defaults/generation and `fromSubject` mappings, list policies, canonical/storage/physical/insert/row/stored representations, and operation input/output/error schemas. It is input to the opt-in admin interface, but presentation configuration is not canonical metadata. Runtime service and transaction metadata remain intentionally opaque; transaction boundaries are authored rather than inferred. ([Inspection](../../packages/effect-domains/src/application-inspect.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

## Evidence Boundary

Previously dated evidence covers one SQLite adapter, the reservation slice, six supporting applications, scoped document authorization, and authenticated todo/note examples.
