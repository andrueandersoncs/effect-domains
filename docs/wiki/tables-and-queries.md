# Tables and Queries

## Decision

This contract includes the approved JSON CLI and imported migration-history cutover. Its [final validation passed](validation-strategy.md#2026-09-10-json-cli-and-imported-migration-history). The preceding [radical simplification passed validation](validation-strategy.md#2026-09-10-radical-simplification); dated evidence for superseded interfaces remains historical.

`Resource.define({ name, schema, authorization, storage?, relations?, capabilities })` is the declarative persistence and routine-RPC interface. `Resource.compile` derives its table, repository, contracts, group, handlers, and exact publication record. `Table.make` remains the lower-level compiler; authored SQL uses Effect `SqlSchema` and native `SqlClient`.

Table names are application configuration; intrinsic identity belongs to the canonical schema through `identifier`. Without one, persistence adds a generated UUIDv7 `id` to its row representation. This cleanly supersedes older interfaces without a compatibility path. ([Domain identity direction](raw/domain-identifier-and-basic-persistence-direction.md); [Clean-cutover direction](raw/refactoring-and-compatibility-direction.md))

## Canonical and Storage Representations

`schema` is the canonical application representation. `storage`, when supplied, is a reversible persistence codec whose decoded fields must exactly match the canonical schema; storage therefore may use runtime dependencies without changing RPC wire contracts. `Table.make` derives physical SQLite fields, `insertSchema`, `rowSchema`, and `storageSchema` from that storage representation. ([Resource](../../packages/effect-domains/src/resource.ts); [Table](../../packages/effect-domains/src/table.ts); [field-note encryption](../../examples/field-notes/storage.ts))

Supported fields compile once to `FieldIR`, a product of physical metadata, codecs, comparison evidence, and retained AST evidence. `SchemaField.fold` provides the one cycle-aware recursion shared by Table and Authorization while keeping their interpretations distinct. ([Field IR and fold](../../packages/effect-domains/src/schema-field.ts); [authorization interpreter](../../packages/effect-domains/src/authorization.ts))

The current compiler supports flat required string, numeric, boolean, nullable scalar, and timestamp fields. Encoded names become columns; recognized checks become SQLite constraints. Arbitrary predicates and root checks remain schema validation, and nested rows, optional keys, bare `Option`, ambiguous identity, and non-scalar storage codecs are not claimed to work. ([Table](../../packages/effect-domains/src/table.ts); [SQLite DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [table regressions](../../test/Table.test.ts))

`CalendarDateSchema` from `effect-domains/domain` validates real Gregorian `YYYY-MM-DD` dates, including leap-century boundaries, without converting them to instants or changing their string representation. Task due dates and expense dates share it; timestamp fields retain their distinct native schemas. ([Domain values](../../packages/effect-domains/src/domain.ts); [task schema](../../examples/team-tasks/domain.ts); [expense schema](../../examples/expense-ledger/domain.ts))

JavaScript string-length checks remain canonical validation rather than SQLite `length` constraints: UTF-16 code units, Unicode code points, and NUL handling are not equivalent. Historical artifacts retain their original DDL; explicit migrations remove the old constraints from current example databases. ([Compiler](../../packages/effect-domains/src/table.ts); [DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [Unicode persistence regression](../../test/Table.test.ts))

## Relational Storage Declarations

Optional `relations` declares `unique`, `foreignKeys`, and `indexes`. Foreign keys target `Resource.reference(target, fields)` rather than repeating a name string. `Resource.define` validates local fields; `Application.compile` requires the exact referenced Resource descriptor to be registered. Same-name replacements fail identity validation.

SQLite derives named table constraints and separate index statements. Foreign keys are enabled on the runtime connection and use SQLite's default `NO ACTION`; no cascade, join, eager loading, or aggregate transaction is inferred. Unique-tuple and primary-key violations surface from `RepositoryStore.insert`/`update` as `UniqueViolation { resource, constraint, fields }`, naming the declared constraint, so authored operations translate them instead of pre-selecting; billing maps them to `DuplicateOrderNumber`/`DuplicateInvoiceNumber`. `Table.project(table, fields)` derives a picked storage codec, its JSON-string variant, and a `json_object` fragment for authored nested read models. ([DDL](../../packages/effect-domains/src/sqlite-ddl.ts); [runtime](../../packages/effect-domains/src/sqlite-bun.ts); [store contract](../../packages/effect-domains/src/repository-store.ts); [billing operations](../../examples/orders-invoices/sqlite.ts))

## Generated Resource Capabilities

`Resource.capabilities(...)` is a closed syntax tree. `Resource.crud()` expands to explicit get/list/create/update/remove nodes; `Resource.patch()` and `Resource.transition()` are separate nodes. The compiler alone derives repositories and published RPCs. Every repository method remains available locally regardless of publication.

The reading-list application uses generated operations for a personal reading backlog; the expense ledger authors queries and currency-separated totals with native SQL. Each owns its canonical domain schema rather than sharing a toy book fixture. Generated remove returns `void`; an authored contract may deliberately return the deleted row. Those semantic differences are not inferred. ([Reading-list resource](../../examples/reading-list/resources.ts); [Expense contracts](../../examples/expense-ledger/sqlite.ts))

`Resource.create({ sources })` assigns one source node per field: `Resource.defaultValue`, `Resource.generated`, or `Resource.fromSubject`. Unassigned fields are caller input and otherwise-unsourced nullable fields receive an implicit null default. Creation input derivation, runtime evaluation, and inspection fold the same source syntax, so they cannot silently disagree.

Subject-source compatibility is directional: a required subject field can populate a nullable destination, but a nullable source cannot populate a required destination. Static definition validation and runtime compilation enforce the same direction.

`Resource.list({ filter, range, order, limit })` declares equality filters, inclusive bounds, fixed ordering, and maximum page size. Every generated list returns `{ items, nextCursor }`; callers never select ordering.

Generated resource lists and `ReadModel.page` compile their SQLite pagination through one private list kernel. Resource retains authorization, entitlement, identifier-tiebreaking, and canonical validation; ReadModel retains joins, qualified projections, and decoding.

`version: "version"` declares optimistic concurrency on a non-nullable integer field: creation writes `1`, `update(row)` treats the submitted version as expected, published patch input becomes `{ key, expectedVersion, changes }`, and every guarded write increments the field in the same `UPDATE … WHERE version = ?`. A row that exists but no longer matches fails with `VersionConflict { resource, key, expectedVersion }`. Published patch input is otherwise `{ key, changes }`; identifier and version fields cannot occur in `changes`, and the merged canonical value is validated before writing. ([Resource](../../packages/effect-domains/src/resource.ts); [store guard](../../packages/effect-domains/src/repository-store.ts); [billing resources](../../examples/orders-invoices/resources.ts); [runtime regressions](../../test/ResourceCrud.test.ts))

`Transitions.make` declares a status machine as data. A Resource spec names it and includes `Resource.transition()` to publish the capability; compilation derives guarded writes and the typed transition error. Transition authorization remains a distinct current/candidate action, and cross-record side effects remain authored commands.

## Resource Authorization

Every resource selects `Authorization.public`, `Authorization.deny`, or `Authorization.for({ resource, subject }).policy({ scope, allow })`. Typed `row`, `next`, and `subject` references compose equality, membership, conjunction, disjunction, and unchanged-field policies; phase typing rejects current-state references in create and candidate-state references in read. `update`, `patch`, and `transition` authorize both current and candidate state through their own action keys. Omitted actions deny. Policy is authored resource configuration, not inferred domain metadata. ([Authorization](../../packages/effect-domains/src/authorization.ts); [type boundaries](../../test/Authorization.types.ts))

Policy construction validates, snapshots, and freezes syntax once, retaining compiled evaluators in private registration state. Fabricated policy descriptors are rejected. Resource binding still checks canonical identity, storage compatibility, and subject bindings; invocation still resolves and validates current authenticated claims. Runtime and SQL interpreters share literal/subject operand resolution, while SQL row identifiers, candidate-phase restrictions, and runtime short-circuiting remain separate. ([Authorization](../../packages/effect-domains/src/authorization.ts); [Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [lifetime regressions](../../test/Authorization.test.ts))

The closed schema-backed `Policy` AST and `PolicyF` fold drive Effect evaluation, parameterized SQL, field references, and rendered inspection. Equality is total over finite scalar values without coercion. SQL visibility accepts identity-compatible string/numeric storage fields, optionally nullable, and native Boolean fields through their SQLite numeric `0`/`1` encoding. Arbitrary semantic Boolean codecs remain rejected for visibility rather than approximated. Standalone evaluation can use Boolean policies. ([Policy](../../packages/effect-domains/src/policy.ts); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [parity regressions](../../test/Policy.test.ts))

`scope` always constrains visibility and current/candidate state. Hidden rows look missing, and list filtering occurs before SQL pagination. Mutations authorize complete candidates, require readable create/update/patch results, and check persisted returned rows. Checks and writes are transactional; repositories do not bypass policy when called from authored Effects. Native `SqlClient` and `RepositoryStore` remain privileged escape hatches. ([Resource](../../packages/effect-domains/src/resource.ts); [SQLite](../../packages/effect-domains/src/sqlite-bun.ts); [authorization regressions](../../test/Authorization.test.ts))

Protected generated RPCs authenticate per request through `AuthorizationRpc.Authenticator`, whose `authenticate(headers)` supplies verified `AuthorizationSubject` claims or fails with `Unauthenticated` or `IdentityUnavailable`. The generic contract remains subject-only: it does not require or disclose opaque session data. Missing authenticators and forged identity headers cannot fall back to a captured subject. The CLI sends `<APP>_TOKEN` as a bearer token; applications may supply custom verified IdP adapters. Authored Effects may supply trusted subjects and use `Authorization.require` with `AuthorizationValues.make({ row, next })`, where row and candidate values are `Option`s. ([RPC authentication](../../packages/effect-domains/src/authorization-rpc.ts); [portable identity](../../packages/effect-domains/src/identity.ts); [identity-isolation regressions](../../test/AuthorizationRpc.test.ts))

`Authorization.subject(SubjectSchema)` supplies typed subject references and the existing equality/membership/boolean operators. Its `.policy(expression, { require? })` validates subject-only references, snapshots the expression, and retains a compiled evaluator. The resulting `SubjectPolicy` is directly acceptable in a resource policy's `scope` and `allow.<action>` slots: its expression is used and its entitlement requirements merge into those actions, so role ladders are declared once (`ExampleRoles.reader/editor/admin`) and reused by every resource and authored operation. `p.sameAs("tenantId")` is the typed tenant/owner scope `eq(row.field, subject.field)`; `includes(subject.roles, "admin")` only accepts a role literal when the subject declares its roles as literals. `Authorization.requireSubject(policy)` requires a trusted `AuthorizationSubject`, returns typed claims, and fails with `Forbidden` for invalid claims or a denied expression. ([Implementation](../../packages/effect-domains/src/authorization.ts); [shared roles](../../packages/example-support/src/subject.ts); [team-task scope](../../examples/team-tasks/resources.ts))

Authored RPCs opt into the same policy with `.middleware(AuthorizationRpc).annotate(AuthorizationRpc.policy, policy)`; groups use `.annotateRpcs(AuthorizationRpc.policy, policy)`. The middleware authenticates on every request, checks the annotated policy before invoking the handler, and supplies only the verified request-local subject. Without an annotation it still authenticates, but adds no role or entitlement requirement. Its declared errors are `Unauthenticated | IdentityUnavailable | Forbidden | EntitlementRequired | EntitlementUnavailable`; operation inspection includes the subject schema, rendered rule, and structured requirements. An annotation alone is not middleware installation, and persisted execution is not a continuing authenticated request. ([RPC middleware](../../packages/effect-domains/src/authorization-rpc.ts); [inspection](../../packages/effect-domains/src/application-inspect.ts); [request isolation regression](../../test/AuthorizationRpc.test.ts))

It uses Argon2id hashes, random Base64URL credentials, persisted SHA-256 digests, expiry/revocation, and insert-once seeds. `ExampleIdentity.layer(application)` is the example-support wrapper supplying the demo accounts and `EFFECT_DOMAINS_DEMO_PASSWORD`. ### Entitlement Gating

Resource policies accept `require: { read: [p.entitlement({ name: "guides.read", key: p.row.id })] }`, alongside ordinary `scope` and `allow` rules. Every requirement in an action's array must pass; a requirement cannot grant an omitted action. Keys are required strings, including branded strings, and obey the same subject/current/candidate phase restrictions as action policies. Construction validates and freezes requirements. Subject policies accept `.policy(expression, { require: [p.entitlement({ name: "reports.generate", key: p.subject.tenantId })] })`; copying only a subject policy's `.expression` does not copy its requirements. ([Declarations](../../packages/effect-domains/src/authorization.ts); [type boundaries](../../test/Entitlements.types.ts))

Applications provide `Entitlements` from `effect-domains/entitlements` through a runtime Layer. `Entitlements.fromTables([new Entitlements.Source({ name, table, subject, key, where, grant })])` derives the common resolver over a registered table: it decodes the subject, selects the row whose `key` column equals the requested key under the `where` equalities, decodes it through the table's storage codec, and applies the authored `grant(row, now)` predicate; unknown names return `false`, and lookup or decode failures become `EntitlementUnavailable`. `has({ name, key, subject })` returns `Effect<boolean, EntitlementUnavailable>`; a negative result becomes `EntitlementRequired { entitlement }`. Subscription state, trials, grace periods, purchases, refunds, and provider synchronization remain application-owned in `grant`. ([Service](../../packages/effect-domains/src/entitlements.ts); [subscription resolver](../../examples/report-exports/subscriptions.ts); [purchase resolver](../../examples/purchased-guides/entitlements.ts))

Subject/literal-key gates run before resource storage access, so a gated empty list fails explicitly. Row-dependent gates run after ordinary SQL visibility and canonical decoding: hidden rows still look missing. Every returned list item must pass; one locked visible item fails the entire page rather than being filtered out, and the cursor lookahead row is not gated. Mutations check complete candidates, read requirements, and persisted returned rows inside the write transaction. The same checks apply through local repositories and `Authorization.require`; `Authorization.requireSubject` enforces subject requirements in authored Effects. ([Resource enforcement](../../packages/effect-domains/src/resource.ts); [authorization](../../packages/effect-domains/src/authorization.ts); [behavior regressions](../../test/Entitlements.test.ts))

Checks are read-only and may run repeatedly, including before and after a write. The framework caches no entitlement decisions, performs no charging or credit consumption, and promises no atomicity with an external billing provider. Account preflight precedes the resource transaction; application-owned resolver consistency and revocation timing remain explicit. Quotas or metered consumption require authored transactional operations, not side effects in `has`. Requirements remain inspectable, but the admin does not infer access or purchase flows from them. ([Runtime](../../packages/effect-domains/src/authorization.ts); [inspection](../../packages/effect-domains/src/application-inspect.ts))

## Commands, Applications, and Admin

Authored commands separate contract from behavior. `Command.define` records name, schemas, policy, transaction mode, and exact Resource/Table/ReadModel dependencies. `Command.implement` attaches the Effect handler; `Command.bundle` composes implementations. The compiler applies JSON codecs, authorization middleware, transactions, and unavailable-error translation.

Local tests use native RPC clients rather than an injectable command service. `RpcService.make({ name, group })` derives typed in-process and protocol clients.

`Application.define` accepts explicit `Part.resource`, `Part.command`, `Part.native`, and `Part.application` syntax. `Application.compile` is the only normalization boundary and yields the authoritative `ApplicationIR`. CLI, MCP, admin, runtime, and inspection consume that IR directly rather than rediscovering parts or duck-typing objects.

Absent CLI input is derived from the operation schema: no-payload RPCs encode/decode their void representation, while empty structs receive `{}`. Payloads with only optional fields also default to `{}`. Explicit input uses only `--input-json`; native application subcommands, help, and local inspection remain, but field flags are removed. ([CLI](../../packages/effect-domains/src/rpc-cli.ts); [live CLI regressions](../../test/RpcCli.test.ts))

The same `serve` runtime mounts Effect RPC at `/rpc/v1` and derived MCP tools at `/mcp`. Its opt-in `admin: true | { path?, presentation?, allowedOrigins? }` additionally serves a generated browser interface at `/admin` by default. [`apps/admin`](../../apps/admin/) is built explicitly with `bun install` then `bun run build`; when admin is enabled, the Bun adapter loads only its prebuilt `dist/client.js` and `dist/style.css` assets. `ApplicationAdmin.layerHttp({ application, javascript, stylesheet, path?, presentation?, allowedOrigins? })` is the lower-level adapter. Admin and MCP invoke the same in-process RPC transport, preserving handlers, middleware, service-dependent codecs, and per-call bearer authentication without persisting a token. ([Browser client](../../apps/admin/src/client.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

Each example also serves a hand-authored [Foldkit](https://foldkit.dev/) page at `/` through application `routes`. `StaticSpa.layerHttp` validates one authored site declaration and owns its prebuilt asset URLs and HTTP routes; `BrowserRuntime.run` owns effectful root-container application startup; and `RpcBrowser` supplies the same-origin `/rpc/v1` protocol plus a request-token-aware command constructor for authored calls. [`packages/example-web`](../../packages/example-web/) contains shared stylesheet/build and authored HTML/session-view presentation only. Canonical schemas stay free of UI metadata. ([Example frontends](../../examples/README.md#foldkit-frontends); [browser transport](../../packages/effect-domains/src/rpc-browser.ts); [static routes](../../packages/effect-domains/src/static-spa.ts))

Framework `Requests` and `Page` retain the primitive ownership/value contracts. `ResourcePager` composes replacement/continuation starts, pending/end guards, and stale page settlement; seven explicit clients plus `ResourceEditor` now exercise it across public, authenticated, filtered, single-page, and multi-list model shapes. `BrowserModel` centralizes notice, field-error, and form-failure values, allowing native field rendering without per-application wrapper nodes. `IdentitySession.embed` maps child commands while parent reducers explicitly decide generation-triggered resets. Public CRUD pages may use `ResourceEditor.make`, which requires exact published list/create/update/remove capabilities; form codecs, copy, filtering, authentication, and business refresh rules remain explicit. ([Browser state](../../packages/effect-domains/src/browser-model.ts); [pager](../../packages/effect-domains/src/resource-pager.ts); [identity controller](../../packages/effect-domains/src/identity-session.ts); [editor](../../packages/effect-domains/src/resource-editor.ts))

`RpcBrowser.query` maps an authored model dependency schema and Effect to a Foldkit subscription backed by native `Reactivity.stream`. `RpcBrowser.mutation` invalidates declared keys only after its Effect succeeds, and `BrowserRuntime.run` installs their shared Reactivity service automatically. `ResourceEditor` uses the exact Resource descriptor as the mechanical key for its base list and generated mutations; filters, session dependencies, explicit continuation, authorization, and non-CRUD policy remain authored. Field Notes validates the authored authenticated/filter-dependent path, while Editorial Calendar validates the contract-derived CRUD path. The transport remains unary `/rpc/v1`: this supplies browser-local invalidation/refetch, not server push, cross-tab notification, or offline replication. ([Browser transport](../../packages/effect-domains/src/rpc-browser.ts); [browser runtime](../../packages/effect-domains/src/browser-runtime.ts); [resource editor](../../packages/effect-domains/src/resource-editor.ts); [reactivity regression](../../test/RpcBrowserReactivity.test.ts))

One handler defect does not terminate unrelated requests sharing the in-process transport. Payload decoding and success/error encoding use the RPC handler's captured service context, not an ambient adapter override; request dispatch remains outside that codec context so per-call authentication is preserved. ([In-process transport](../../packages/effect-domains/src/rpc-in-process.ts); [admin regressions](../../test/ApplicationAdmin.test.ts); [MCP regressions](../../test/RpcMcp.test.ts))

The admin uses inspection to generate operation forms, resource lists, declared filters, cursor paging, and a complete-JSON fallback. It presents optional application-supplied titles, labels, columns, and descriptions, none of which becomes canonical resource or operation metadata. Server-side schemas and authorization remain authoritative; the interface infers no permissions. Its browser API accepts same-origin calls and trusts loopback hosts by default. A non-loopback host must name exact `allowedOrigins`; this is an origin check, not a CORS grant. ([Admin client](../../apps/admin/src/client.ts); [Admin stylesheet](../../apps/admin/src/style.css); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Inspection](../../packages/effect-domains/src/application-inspect.ts))

## Native Durable Execution

Application `parts` accept native `{ group, handlers }` bundles. `WorkflowProxy.toRpcGroup` / `WorkflowProxyServer.layerRpcHandlers` and `EntityProxy.toRpcGroup` / `EntityProxyServer.layerRpcHandlers` therefore compose directly when their payloads already match the application boundary. Report exports instead author native RPC handlers to bind trusted account identity before native workflow execution; this is explicit policy, not a second workflow contract. Native unary procedures retain generated CLI, MCP, and inspection support. Authenticate and authorize published operations explicitly, including submission, resume, and polling: persisted execution is not an authenticated HTTP request, and inner protocol annotations do not automatically protect a proxy boundary. ([Report commands](../../examples/report-exports/workflow.ts); [entity proxy](../../examples/appointment-reminders/appointment-reminder-entity.ts); [proxy regression](../../test/WorkflowApplication.test.ts))

Applications compose native SQL-backed execution layers in `services`, explicitly using `Layer.provide(privateSqlite)` so the private connection does not become application SQL. The [shared example helper](../../packages/effect-domains/src/sqlite-bun.ts) checks the opened connections' file paths and inodes before native execution services initialize their tables. This is application-level composition, not framework runtime policy. The old `execution` option, pre-open alias rejection, and URL/dangling-symlink guarantees are removed. Opening a file may already have filesystem effects; concurrent filesystem replacement is not guarded. Framework resource history manages only the application database; native Effect services own their execution tables and migrations. ([Workflow entrypoint](../../examples/report-exports/main.ts); [reminder entrypoint](../../examples/appointment-reminders/main.ts); [runtime](../../packages/effect-domains/src/application-bun.ts))

`SqliteBunRuntime.privateClient({ application, purpose })` captures application SQL, opens native SQLite, and checks opened-file identity before execution services initialize. The version-sensitive `@effect-domains/example-support/cluster-runtime` module composes native single, Bun HTTP runner, and client-only layers; exact Effect release-candidate pins and focused compatibility checks contain API churn without recreating a framework Cluster facade. `replaceFileAtomically({ path, contents })` shares same-directory temporary-file creation, write, rename, and scoped cleanup. Destination selection, serialization, idempotency, and failure policy remain authored. ([Database helper](../../packages/effect-domains/src/sqlite-bun.ts); [Cluster boundary](../../packages/example-support/src/cluster-runtime.ts); [file helper](../../packages/example-support/src/files.ts))

`background` accepts a native `Layer` for workflow registrations, queue consumers, entity registrations, singletons, or cron tasks. It starts after application services and initialization under both `serve` and the conditionally available `worker` command. `clusterWorkerLayer` omits runner registrations in `client` mode; the report application still starts its scoped transactional-outbox relay there. Long-lived loops must fork in the layer scope so acquisition completes. `worker` opens no application HTTP listener. `routes` accepts native `HttpRouter` layers for `serve`. Neither option changes canonical schemas or derives business policy. ([Runtime](../../packages/effect-domains/src/application-bun.ts); [workflow composition](../../examples/report-exports/runtime.ts))

Native Sharding supplies its own private `SqlClient` during Entity and ClusterCron execution. Code that needs application SQL must capture the application connection in its registration layer, or provide a narrow application store whose methods close over that connection. Merely omitting private SQL from the outer execution output does not override native invocation context. The reminder registrations explicitly capture application SQL before constructing handlers and retention work. ([Reminder background](../../examples/appointment-reminders/background.ts))

The workflow application reads native `Sharding` and `RunnerStorage` services for runner health, active-entity count, and shutdown state. Its private response schemas and authenticated `ReportExport.Status` command are application-owned; the framework has no cluster-diagnostics wrapper. The example separately authenticates `/operator/metrics` before formatting native Prometheus metrics. Keep diagnostics exposure and authorization explicit. ([Status command](../../examples/report-exports/workflow.ts); [metrics route](../../examples/report-exports/routes.ts))

The examples support native `single`, HTTP `runner`, and `client` modes. Concurrent evidence is deliberately bounded to colocated runners sharing one execution SQLite file: two report runners split 64 shards evenly, the owning process stopped while a persisted approval workflow waited, its shard moved to the survivor, and a client-only application released and completed the same execution. Startup stores and compares topology version, shard count, and groups; authored compare-and-set upgrades plus a documented stop-all order cover incompatible topology/storage changes. Report acceptance is an application-owned transactional outbox with at-least-once deterministic dispatch. Infrastructure defects suspend for explicit same-execution resume; cancellation is explicit. Its immutable artifact sink plus reconciliation handles the demonstrated external effect without claiming cross-database transactions or general exactly-once delivery. The reminder retains deduplicated in-app delivery, a singleton projection, and UTC retention scheduling. ([Cluster runtime](../../packages/example-support/src/cluster-runtime.ts); [execution store](../../examples/report-exports/executions.ts); [workflow](../../examples/report-exports/workflow.ts); [writer](../../examples/report-exports/writer.ts); [reminder background](../../examples/appointment-reminders/background.ts))

Field Notes now supplies bounded native integration evidence without adding canonical metadata. A typed `NoteEdited` EventLog persists to SQL journals, synchronizes two replicas, deduplicates replay, rebuilds its projection after restart, and converges conflicts by authored `(revision, replicaId)` ordering. Separately, its real Foldkit client declares an authenticated/filter-dependent `RpcBrowser.query`; successful save/remove mutations invalidate the exact `FieldReportsResource` key and automatically refetch the mounted list. Editorial Calendar exercises the same framework contract through derived `ResourceEditor` CRUD. Event conflict policy remains application-owned, while browser cache invalidation is mechanical client configuration. ## Authored Queries

Effect `SqlSchema.findOne`, `findOneOption`, and `findAll` encode requests and decode SQL results while retaining codec-service dependencies. Authored effects use the same native `SqlClient` supplied to generated repositories, so their transaction boundaries compose. Explicit schema encode/decode remains available when upstream SQL cardinality semantics do not fit. ([Expense queries](../../examples/expense-ledger/sqlite.ts); [SQLite integration](../../test/SqliteBun.test.ts); [runtime](../../packages/effect-domains/src/sqlite-bun.ts))

Expense record/get/update reuse the existing resource repository beneath their authored RPC contracts, translating repository failures explicitly. Range queries and currency-local totals compose native SQL predicates; removal retains atomic `DELETE ... RETURNING` because its result is the deleted expense rather than generated remove's void result. Billing aggregate JSON fields use `Schema.fromJsonString` inside `SqlSchema` result decoding, with native optional-row lookup for invoices. Its `NestedRow.make({ table, fields })` is an example-local projection helper: it derives nested JSON keys and result codecs from compiled physical column storage schemas, including Boolean/timestamp representations. Tenant correlation, ordering, null invoices, totals, versions, and transactions remain authored; this is not a generic ORM, relation planner, or query wrapper. ([Expense handlers](../../examples/expense-ledger/sqlite.ts); [billing projections](../../packages/effect-domains/src/table.ts); [billing SQL](../../examples/orders-invoices/sqlite.ts))

Generated repositories and authored SQL operate on persisted state without a framework-owned cache. Applications needing cached state must explicitly own invalidation and concurrency policy; a process-local synchronized value cannot provide database-wide conflict detection. ([Expense queries](../../examples/expense-ledger/sqlite.ts); [transactional reservation policy](../../examples/reservations/sqlite.ts))

### Declared Joined Projections

`ReadModel.define({ tables, from, joins, select })` records explicit source resources, inner/left equality joins, and recursive schema-backed selection syntax. `ReadModel.fold` supplies the one recursion used for SQL metadata, dependency/inspection data, and compiled result schemas. `ReadModel.page` adds equality/range/keyset policy; `ReadModel.compilePage` derives the executable page IR; `ReadModel.publish` derives its command implementation.

The same private SQLite list kernel renders filters, inclusive ranges, lexicographic keysets, and ordering for ReadModel pages and generated resource lists. Resource supplies physical table identifiers; ReadModel supplies qualified projected columns. Join construction, result codecs, authorization predicates, and table execution remain separate.

Selected field codecs retain service requirements and decode storage values once. Left-joined fields become nullable. The compiler rejects incompatible physical join scalars, malformed join graphs, nullable ordering/range fields, and encoded nullable fields whose stored `null` cannot distinguish an unmatched row. Aggregates and ambiguous null semantics remain authored conversions. ([ReadModel compiler](../../packages/effect-domains/src/read-model.ts); [regressions](../../test/ReadModel.test.ts); [type boundaries](../../test/ReadModel.types.ts))

Application composition validates ReadModel dependencies against the exact registered resource identities. Inspection reads the already-normalized `ApplicationIR` and exposes aliases, joins, selections, and physical table names without rediscovering syntax.

Repair Workshop and Support Cases publish materially different bounded boards through `ReadModel.publish`. Their nested/aggregate queries remain authored SQL; this boundary does not claim general relationship loading.

## SQLite Migrations and Inspection

`SqliteMigrations.make({ id, to, steps })` constructs a frozen explicit migration artifact; the starting snapshot is never written because history validation already requires it to equal the preceding artifact's `to` (or the empty schema). `initial({ id, tables })` derives fresh table and declared-index creation from supported table definitions. `snapshot(tables)` captures a physical target. `history(...artifacts)` decodes and validates ordered imported JSONs synchronously at module load; `decodeHistory(raw)` is the Effect form. Startup accepts `database: { migrations: history, filename?: string }`. There is no manifest, loader, planner, generator, intent DSL, or schema CLI. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [authoring walkthrough](../../examples/README.md#review-schema-changes))

`SqliteMigrations.steps` exposes the `CreateTable`, `AddColumn`, `RenameColumn`, `RebuildTable`, `CreateIndex`, and `DropIndex` schema constructors. Steps reference tables and indexes in `to.tables` by name rather than embedding snapshots, so each artifact carries one copy of every physical table. Rebuild copies list only what is not an identity copy: a column present in both the preceding and target snapshots and absent from `copies` copies itself, while a new column without an authored `SqliteMigrations.copies.Value` or `.Expression` is a validation error. Authors still choose steps, constants, and SQL expressions; the framework does not infer renames, backfills, transformations, or a safe change sequence. Rebuild expressions read the original source table. The v2 artifact format replaced v1 without a ledger compatibility path; existing development databases must be recreated. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

One private exhaustive interpreter compiles the existing nonrecursive step union to ordered SQL statements. A separate exhaustive copy interpreter handles original columns, parameterized constants, and authored SQL expressions. Transactional execution and target/foreign-key verification remain outside those compilers; this introduces no new migration DSL. ([Migration interpreters](../../packages/effect-domains/src/sqlite-migrations.ts))

Each table-bearing example imports ordered artifact JSONs in `migrations.ts` and exports `SqliteMigrations.history(...)`, which `main.ts` supplies to `ApplicationBun.run`. The workflow-only example has no application tables and supplies empty history. Historical seed code can decode a prefix of the frozen chain. Keep historical JSON frozen; review and append new artifacts and their imports explicitly. Single-artifact examples whose physical snapshot changed this pass (billing versions and derived names, workshop names, report subscription timestamps) regenerated their initial artifact instead of appending. There is no framework artifact-writing or atomic history-registration command. ([Workflow entrypoint](../../examples/report-exports/main.ts); [billing fixture](../../examples/orders-invoices/migrations.ts); [document seed](../../examples/editorial-calendar/seed-v1.ts))

Every nonempty managed schema requires an initial migration. There is no artifact-free bootstrap or adoption path: the applied-artifact ledger determines expected state. Runtime validates ordered history, immutable applied artifacts, and the actual current schema before replay. Pending migrations apply transactionally, and their resulting schema must exactly match the target. Empty schemas may use empty history. Nullable physical identifiers are rejected when loading snapshots or migration history. ([Migration store](../../packages/effect-domains/src/sqlite-migrations.ts); [migration regressions](../../test/SqliteMigrations.test.ts))

The [task](../../examples/team-tasks/migrations/003_schema_string_checks.json), [editorial](../../examples/editorial-calendar/migrations/003_schema_string_checks.json), and [reservation](../../examples/reservations/migrations/003_schema_string_checks.json) histories append explicit identity-copy rebuilds removing misderived string-length constraints. Existing artifacts and the historical DDL renderer are unchanged.

Authors express declared index changes with create/drop-index steps and unique/foreign-key changes with explicit table rebuilds. Replay defers foreign-key checks inside the migration transaction, verifies the final schema and `foreign_key_check`, clears SQLite's deferred-counter state, and records the artifact before commit. Invalid existing rows roll back the migration and ledger together. Exact declared index SQL is verified; untracked indexes and triggers remain drift. Historical artifacts without relational metadata retain their original serialization. ([Explicit artifacts and replay](../../packages/effect-domains/src/sqlite-migrations.ts); [rollback, parent-rebuild, and index-drift regressions](../../test/RelationalMigrations.test.ts))

Relational declarations are exposed as `storage.physical.relations` in inspection. They describe storage structure, not query dependencies or transaction boundaries. ([Inspection](../../packages/effect-domains/src/application-inspect.ts))

`inspect` emits canonical resource schemas, authorization subject schemas and rendered scope/action policies, compiled creation defaults/generation, including implicit UUID identity, and `fromSubject` mappings, `operations.list` policy, canonical/storage/insert/row/stored representations, JSON-encoded native `Table.snapshot` physical metadata, and operation input/output/error schemas. It is input to the opt-in admin interface, but presentation configuration is not canonical metadata. It does not create opaque runtime metadata for handler services or transactions; those boundaries remain authored and uninspectable. ([Inspection](../../packages/effect-domains/src/application-inspect.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

## Evidence Boundary

Previously dated evidence covers one SQLite adapter, the reservation slice, six supporting applications, scoped document authorization, and authenticated todo/note examples. It does not establish another database, relationships, indexes, a production identity provider, retries, idempotency, distributed coherence, or a materially different business-policy domain, and does not itself validate later changes. ([Example verification](validation-strategy.md#2026-09-09-authorized-examples); [Authorization verification](validation-strategy.md#2026-09-08-resource-authorization); [Project thesis](raw/project-thesis.md))

The newer [durable-execution verification](validation-strategy.md#2026-09-09-native-durable-execution) establishes bounded restart recovery, idempotent replay of the demonstrated effects, and selective native scheduling composition. It does not establish multi-runner coordination, cross-database atomicity, arbitrary external-effect idempotency, or a general actor/job framework.

The [orders/invoices verification](validation-strategy.md#2026-09-09-tenant-scoped-orders-and-invoices) adds bounded evidence for composite relationships, declared indexes, tenant-scoped multi-resource commands, and database-guarded stale-write rejection in a second business domain. It does not establish another database, production identity, billing-provider integration, automatic joins, or general conflict-resolution policy.
