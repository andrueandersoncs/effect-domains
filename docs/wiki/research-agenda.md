# Research Agenda

This page distinguishes the implemented API from evidence still needed to judge the project hypothesis. Mechanical, lossless derivation remains the boundary; business policy and semantic transformations remain authored. ([Project thesis](raw/project-thesis.md))

## Framework Direction

The intended product is conventionally generated application infrastructure for Effect: authors declare canonical schemas, select generated resource capabilities, and write commands and policies whose semantics are not in those schemas. Current evidence includes SQLite reservation policy, tenant-scoped orders/invoices, and two materially different native execution integrations: durable export/approval and scheduled per-recipient delivery. These bounded demonstrations do not establish general business-domain fit. ([Effect and declarative interface direction](raw/effect-and-declarative-interface-direction.md); [Verification limits](validation-strategy.md#evidence-boundary))

### Implemented contract

The 2026-09-11 abstraction pass supersedes the descriptions below it where they differ; its [validation record](validation-strategy.md#2026-09-11-abstraction-pass) separates exercised behavior from remaining claims. The approved JSON CLI and imported migration-history cutover ([validation](validation-strategy.md#2026-09-10-json-cli-and-imported-migration-history)) and the [2026-09-10 radical simplification](validation-strategy.md#2026-09-10-radical-simplification) remain the preceding baselines; earlier observations apply only to their dated revisions.

Supported fields compile to one product of physical metadata, codecs, and comparison evidence. Table and Authorization share a private scalar-schema fold, retaining AST evidence while separating storage and canonical interpretations. A private creation-source language (`Input`, `Default`, `Generated`, `Subject`) compiles accepted input and value evaluation together, validates sources, and supplies inspection metadata, including implicit UUID generation. Closed resource operation descriptors drive repository/native RPC construction. The existing closed policy algebra retains private compiled authorization registration. These small internal languages do not introduce a universal framework, user-facing source DSL, or parallel transport DTO. ([Scalar fold](../../packages/effect-domains/src/schema-algebra.ts); [Table](../../packages/effect-domains/src/table.ts); [creation compiler](../../packages/effect-domains/src/resource-creation.ts); [Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts))

- `Resource.make({ name, schema, authorization, operations, storage?, relations?, version?, transitions? })` derives a storage table, policy-enforcing canonical repository, and only the RPC procedures selected by the single `operations` record. `Resource.crud` is the frozen CRUD selection; `patch: true` and `transition: true` select those operations. All repository methods remain available locally, including `ensure(row)` and `transition(...)`. Authorization must explicitly select public, deny, or a typed resource policy. `storage` is a reversible representation with the same decoded fields as the canonical schema. ([Resource](../../packages/effect-domains/src/resource.ts); [contract](tables-and-queries.md#generated-resource-operations))
- `effect-domains/domain` exports the shared value schemas `CalendarDateSchema`, `UuidV7Schema` (the generated identifier format), `SafeIntSchema`, `NonNegativeSafeIntSchema`, `PositiveSafeIntSchema` (SQLite INTEGER-safe bounds), and `PageLimitSchema` (1–100). `Authorization.for(...)` adds `sameAs(field)` and accepts `SubjectPolicy` values in `scope`/`allow`, merging their entitlement requirements; `includes` is literal-aware. Example roles are declared once in example-support and reused. ([Domain values](../../packages/effect-domains/src/domain.ts); [subject policy embedding](../../packages/effect-domains/src/authorization.ts); [shared roles](../../packages/example-support/src/subject.ts))
- `operations.create` is the only creation configuration: `defaults`, runtime `generated` tokens, policy-authorized `fromSubject`, plus an implicit `null` default for every otherwise-unsourced nullable field. `operations.list` declares equality `filter`, inclusive `range` bounds, a fixed `order` ending in the identifier, and `limit`; pages are keyset-paged `{ items, nextCursor }` with default limit 50. Clients never choose ordering. ([Resource](../../packages/effect-domains/src/resource.ts); [store keyset](../../packages/effect-domains/src/sqlite-bun.ts); [resource regressions](../../test/ResourceCrud.test.ts))
- `version` declares optimistic concurrency on an integer field: create writes `1`, update/patch/transition guard `WHERE version = ?` and increment, and a mismatched existing row fails with `VersionConflict`. `Transitions.make({ name, field, status, transitions })` declares a status machine as data; `Resource.make({ transitions })` derives the guard, the status-guarded write, the `Invalid<Name>Transition` error, and the `<resource>.transition` RPC `{ key, action, changes?, expectedVersion? }`. Transition has its own current/candidate authorization action rather than reusing patch permission. Side effects stay authored inside the operation's transaction. `RepositoryStore.update` takes an equality `guard`; declared unique-tuple violations surface as `UniqueViolation` naming the constraint. ([Transitions](../../packages/effect-domains/src/transitions.ts); [Resource](../../packages/effect-domains/src/resource.ts); [authorization regression](../../test/Authorization.test.ts))
- Relation `name`s derive as `<table>_<snake fields>_key|_fkey|_idx` unless authored; foreign keys use `Table.reference(targetTable, fields)` and accept `scope` fields prepended to both sides. Target fields are typed and application composition requires the exact target table descriptor. `Table.project(table, fields)` derives a picked storage codec and `json_object` fragment for authored nested read models. Nothing infers joins, cascades, or indexes. ([Table](../../packages/effect-domains/src/table.ts); [relational contract](tables-and-queries.md#relational-storage-declarations))
- `SqliteView.make({ tables, from, joins, select })` compiles explicitly declared inner/left equality joins and flat selected fields into native SQL fragments and an exact physical-to-canonical result codec. `SqliteView.list({ view, filter?, range?, order, limit? })` derives a bounded typed keyset-page operation fragment. Normalized operation dependencies accept Resources, Tables, and views; application composition validates exact registered table identities and inspection exposes declared `views`. Authorization and transactions remain authored. ([Contract](tables-and-queries.md#declared-joined-projections); [bounded regression](../../test/SqliteView.test.ts))
- Authorization scope is mandatory and conjoined with action rules. Hidden rows look missing; SQL filters before pagination; mutations check current/candidate state and readable results transactionally. A closed policy fold drives evaluation, SQL, references, and inspection. SQL visibility accepts native Boolean values through SQLite `0`/`1`, but rejects semantic Boolean codecs. Protected RPCs require request-local subjects through `AuthorizationRpc.Authenticator`; authored SQL remains privileged. ([Authorization contract](tables-and-queries.md#resource-authorization); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [authorization regressions](../../test/Authorization.test.ts); [RPC identity regressions](../../test/AuthorizationRpc.test.ts))
- Portable `effect-domains/identity` contains only credential/session/subject schemas, `IdentityUnavailable`, and the narrow `IdentityRuntime`. Native `effect-domains/identity-rpc` defines `IdentityRpcs`, `IdentityHandlers`, `authenticateIdentity(headers)`, and the composable `IdentityBundle`. `SqliteIdentity.layer({ application, accounts, password, sessionLifetime?, filename? })` is the framework credential store: account/session `Table`s prepared through the normal migration path on `SqliteBunRuntime.privateClient({ application, purpose })`, which resolves `<APP>_<PURPOSE>_DB` and refuses the application database file/inode. It remains a bounded demo store, not a production IdP. ([Portable interface](../../packages/effect-domains/src/identity.ts); [SQLite identity](../../packages/effect-domains/src/sqlite-identity.ts); [private client](../../packages/effect-domains/src/sqlite-bun.ts))
- Declarative entitlement requirements supplement, never replace, ordinary authorization. `p.entitlement({ name, key })` binds a string key; resource and subject policies share the runtime `Entitlements` service. `Entitlements.fromTables([new Entitlements.Source({ name, table, subject, key, where, grant })])` derives the table-backed resolver so only the `grant(row, now)` predicate is authored. Missing grants and unavailable resolvers have distinct typed failures; checks never charge or consume credits. ([Contract](tables-and-queries.md#entitlement-gating); [service](../../packages/effect-domains/src/entitlements.ts); [regressions](../../test/Entitlements.test.ts))
- `Operation.make({ name, payload?, success, errors?, unavailable, policy?, transaction?, dependencies?, handler })` and `Operation.bundle(...)` compile authored operations: JSON codecs, optional `AuthorizationRpc` policy with a typed subject argument, optional `RepositoryStore.transaction`, normalized Resource/Table/view dependencies, and total translation of undeclared failures into the required `unavailable` error. `unavailable` is mechanically included in the public error union; `errors` lists domain failures only. Native `Rpc.make`/`RpcGroup.make` bundles still compose directly (workflow and entity proxies), and native dependencies use `Operation.annotation` with `Operation.dependencies(...)`. `Application.make({ name, parts })` accepts Resources, bundles, and nested Applications; duplicate table and operation names are rejected. ([Operation](../../packages/effect-domains/src/operation.ts); [Application](../../packages/effect-domains/src/application.ts); [operation regressions](../../test/Operation.test.ts))
- `ApplicationBun.run(application, { database, services?, initialize?, background?, routes?, admin? })` returns the Bun entrypoint `Effect` for native `BunRuntime.runMain`. Database configuration is `{ migrations, filename? }` with decoded ordered history, not a manifest. Startup prepares application storage, builds application services, initializes, registers background layers, and launches HTTP or a worker lifetime. Native execution services compose in the authored `services` layer; there is no `execution` option or framework filename-isolation policy. `worker` exists only with `background`; native HTTP `routes` run only under `serve`. The runner never builds browser assets. ([Bun runtime](../../packages/effect-domains/src/application-bun.ts); [native execution contract](tables-and-queries.md#native-durable-execution))
- `ApplicationBun.run` also accepts declarative `telemetry` export configuration. With a configured OTLP endpoint, native Effect tracing covers server, remote CLI, admin/MCP in-process dispatch, and worker lifetimes; no handler or canonical-schema annotations are added. Endpoint, HTTP JSON/protobuf protocol, resource metadata, collector headers, batching, and shutdown timeout are configurable; deployment `OTEL_*` values supply omitted settings. No endpoint means no export; `telemetry: false` preserves externally supplied tracing. This is tracing integration, not a metrics/logging SDK or a new RPC instrumentation layer. ([Runtime reference](../reference/runtime.md#opentelemetry-tracing); [telemetry layer](../../packages/effect-domains/src/application-telemetry.ts); [live verification](validation-strategy.md#2026-09-11-automatic-rpc-telemetry))
- `serve` derives a Streamable HTTP MCP endpoint at `/mcp` from the application RPC group and can opt into browser admin with `admin: true` or `{ path?, presentation?, allowedOrigins? }`, defaulting to `/admin`. The private Bun workspace builds [`apps/admin`](../../apps/admin/) explicitly with `bun install` then `bun run build`; the runtime loads only its prebuilt `dist/client.js` and `dist/style.css`. MCP and admin both call the same native in-process RPC transport, so handlers, middleware, service codecs, and request bearer authentication remain authoritative per call; no token is persisted. Admin generates forms, resource lists, filters, cursor navigation, and a JSON fallback from inspection. Presentation is display-only configuration; it neither changes canonical metadata nor infers permission. Browser calls must be same-origin. Loopback is trusted by default; a non-loopback host must explicitly configure exact `allowedOrigins`, which does not grant CORS. ([Browser client](../../apps/admin/src/client.ts); [Browser stylesheet](../../apps/admin/src/style.css); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts))
- In-process RPC defects are request-local. Admin/MCP codecs use captured handler services, while authentication remains request-local. CLI input uses only `--input-json`; field flags are removed while native subcommands, help, and inspection remain. No-payload CLI input is schema-derived rather than assumed to be an empty object; empty structs and all-optional payloads default to `{}`. ([Transport](../../packages/effect-domains/src/rpc-in-process.ts); [CLI regressions](../../test/RpcCli.test.ts); [adapter regressions](../../test/ApplicationAdmin.test.ts))
- `RpcService.make({ name, group })` derives a `Context.Service` of the object `RpcClient` for that group. `.layer` is in-process no-serialization dispatch into installed handlers; `.layerProtocol` requires `RpcClient.Protocol`. Example Foldkit pages use `browserLayer(service)` for same-origin `/rpc/v1`. This is a typed client, not a command-service or handler wrapper. ([Service](../../packages/effect-domains/src/rpc-service.ts); [browser layer](../../packages/example-web/src/rpc.ts); [regressions](../../test/RpcService.test.ts))
- Every example browser page is a native `RpcClient` over its existing resource/native groups and same-origin `/rpc/v1`. `effect-domains/requests` owns optional per-key/epoch request ownership, and `effect-domains/form` owns reversible text/number/nullable codecs plus field-error projection. `ResourceEditor.make({ name, resource, form, empty, notices, formatError })` is the narrow Foldkit adapter for public, unfiltered `Resource.crud` pages: it derives the client service, model/messages/commands, cursor accumulation, whole-form decode/row encode, stale-result rejection, and authoritative list reload after save/remove. The form codec, empty values, notices, RPC error display, and complete view remain authored presentation; filtered lists, credentials, mutation refresh alternatives, authorization semantics, and non-CRUD workflows remain application-owned. ([Resource editor](../../packages/effect-domains/src/resource-editor.ts); [Form codecs](../../packages/effect-domains/src/form.ts); [request ownership](../../packages/effect-domains/src/requests.ts); [editorial consumer](../../examples/editorial-calendar/web/main.ts))
- `SqliteMigrations.make({ id, to, steps })` constructs an explicit v2 artifact without a `from` snapshot; `CreateTable`, `RebuildTable`, and `CreateIndex` steps reference `to.tables` by name and rebuilds list only non-identity copies. `initial({ id, tables })` derives fresh creation; `history(...artifacts)` decodes and validates synchronously, `decodeHistory(raw)` as an Effect. There is no `plan`, `generate`, intent DSL, schema CLI, or v1 ledger compatibility. Example artifacts shrank from 4,938 to 2,665 JSON lines. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [migration contract](tables-and-queries.md#sqlite-migrations-and-inspection))
- `inspect` emits generated operation input/output/error schemas and resource canonical schema, creation/list policy, including implicit UUID generation and rendered `fromSubject` mappings, storage schema, and the physical table as JSON-encoded `Table.snapshot`; it does not maintain a duplicate physical DTO. Physical field generation uses the native `generation` key, not `generated`. It provides the descriptive input for admin generation, while presentation stays external. There is no opaque runtime placeholder: handler services and transaction boundaries remain deliberately uninspectable rather than invented metadata. ([Inspection](../../packages/effect-domains/src/application-inspect.ts); [Table](../../packages/effect-domains/src/table.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts))
- Native workflow/entity proxy bundles compose directly in `Application.parts`; native registration and queue-worker layers compose in `background`. Applications supply private execution SQL with `Layer.provide` when composing native execution layers into `services`, without exporting that SQL as application SQL. The shared example helper checks opened database paths/inodes before native execution tables initialize; it does not promise pre-open URL or dangling-symlink rejection. Application Entity/Cron work captures its application database connection before native Sharding supplies its invocation context. The workflow application owns its diagnostic schemas and reads native `Sharding` and `RunnerStorage` services directly. ([Workflow runtime](../../examples/report-exports/runtime.ts); [reminder registration](../../examples/appointment-reminders/background.ts); [diagnostics](../../examples/report-exports/workflow.ts))

Publication and runtime configuration remain outside canonical schemas. Intrinsic identity is domain metadata; generated persistence identity is an adapter concern. Native RPC declarations belong to the operation-contract layer and do not select HTTP transport; applications compose parts and may opt into administration without adding UI metadata to domain schemas. The clean cutover leaves no legacy top-level resource `create`/`list`, command-service representation, or compatibility adapter. ## Established Persistence Findings

`Table.make` compiles supported flat canonical fields to reversible storage codecs and SQLite fields. An explicit `identifier` remains the key; otherwise persistence adds UUIDv7 `id` to the row representation. The compiler supports string, numeric, boolean, nullable scalar, and timestamp representations, not arbitrary nested or optional-key models. ([Table](../../packages/effect-domains/src/table.ts); [table regressions](../../test/Table.test.ts))

Compiled column codecs preserve suspended scalar mappings and exact-filter semantics; nullable physical identifiers are rejected. Canonical JavaScript string-length checks are not SQLite constraints. Explicit example rebuilds remove old misderived constraints without reinterpreting frozen history, and interacting renames copy original source values. ([Persistence contract](tables-and-queries.md#canonical-and-storage-representations); [migration contract](tables-and-queries.md#sqlite-migrations-and-inspection))

Table/Resource `relations` now declares named composite uniqueness, foreign keys, and ordinary secondary indexes outside canonical schemas. Complete-graph validation checks physical targets; SQLite enables foreign keys and migration history manages constraint rebuilds and explicit index steps. No join or cascade policy is inferred. ([Relational contract](tables-and-queries.md#relational-storage-declarations); [migration regressions](../../test/RelationalMigrations.test.ts))

Generated repositories handle routine persistence; authored operations use native Effect `SqlSchema` and `SqlClient`, or explicit schema conversions. There is no framework `Query` descriptor or persistent-reference cache. Transactions, caching, invalidation, and concurrency policy remain explicit application concerns. ([Authored SQL](../../examples/expense-ledger/sqlite.ts); [transactional reservation policy](../../examples/reservations/sqlite.ts))

The example abstraction pass reuses those existing repositories for expense create/find/update, native SQL fragments for range predicates, and `Schema.fromJsonString` for billing projections. Private SQLite composition and atomic file replacement are shared example-support utilities, not framework execution or filesystem policy. The user approved removing mandatory unused schema interfaces by retiring only `schema-record-interface`; all other lint rules remain enabled. ([Expense SQL](../../examples/expense-ledger/sqlite.ts); [billing SQL](../../examples/orders-invoices/sqlite.ts); [example support](../../packages/example-support/src/); [lint configuration](../../better-typescript.json); [verification](validation-strategy.md#2026-09-10-shared-example-abstractions))

The orders/invoices `NestedRow.make({ table, fields })` helper is explicitly example-local. It derives nested JSON selection keys and result codecs from compiled column storage schemas, including physical Boolean/timestamp forms; it does not introduce an ORM or automatic relationship planner. The reservations resource keeps a private generated creation policy (`held`, UUIDv7, current timestamp) for its authored reserve transaction, with no public `reservations.create` operation. ([Billing projection](../../packages/effect-domains/src/table.ts); [reservation resource](../../examples/reservations/resources.ts); [reservation policy](../../examples/reservations/sqlite.ts))

## Application Evidence

Examples are domain-first applications rather than framework-feature fixtures: reading lists, expenses, team tasks, field reports, editorial planning, equipment records, reservations, billing, financial exports, and appointment notifications. Basic examples remain generated CRUD where editing records is the actual use case; authored queries, business commands, and durable workflows remain explicit where semantics require them. Each application owns its canonical schema. ([Application guide](../../examples/README.md); [Reservation policy](../../examples/reservations/sqlite.ts); [Expense queries](../../examples/expense-ledger/sqlite.ts))

Team tasks preserve tenant/owner visibility and completion locks. Shared field notes use reader/editor/admin role membership independently of their encrypted text codec. The shared example identity store issues and verifies opaque credentials against current account state, but it is not a production user-management system or IdP. ([Task rules](../../examples/team-tasks/resources.ts); [Field-note rules](../../examples/field-notes/resources.ts); [Example identity](../../packages/example-support/src/identity.ts))

The resource-focused applications opt into admin; equipment registration is exercised by an official MCP SDK client, and the durable applications expose RPC/CLI/MCP without admin. Field-note storage replaces only the canonical body field with an explicit service-dependent encryption codec; it is not full-database encryption. ([Example entrypoints](../../examples/); [Field-note codec](../../examples/field-notes/storage.ts))

The dated [authorized-example verification](validation-strategy.md#2026-09-09-authorized-examples) and [authorization verification](validation-strategy.md#2026-09-08-resource-authorization) remain historical evidence for their exercised policy, codec, migration, identity-isolation, SQL-parity, and type-boundary interfaces. They are not a claim that later implementation changes have been validated.

Report exports compose approval, durable timing, an activity, and queue-backed JSON artifact creation. Appointment reminders compose persisted per-recipient scheduling, deduplicated in-application notifications, a singleton projection, and cron retention. Earlier generic export/reminder fixtures exercised forced restart and worker recovery; those dated observations are not automatically evidence for every new domain rule. Neither application claims external email/SMS delivery or production identity. ([Historical durable verification](validation-strategy.md#2026-09-09-native-durable-execution); [report runbook](../../examples/report-exports/README.md); [reminder runbook](../../examples/appointment-reminders/README.md))

Report generation now requires an editor role and a current account subscription. Authored native RPC handlers bind workflow identity to the authenticated account while preserving the full report input; global admin operators retain release, recovery, polling, and metrics access independently of payment. Purchased guides demonstrate a distinct per-user, per-resource grant checked after tenant visibility. Both resolvers read persisted application facts on each check, and idempotent seeds preserve expiry and refunds across restart. These examples do not implement a billing provider, webhook reconciliation, checkout, quotas, or distributed entitlement consistency. ([Report policy](../../examples/report-exports/authorization.ts); [account binding](../../examples/report-exports/workflow.ts); [guide policy](../../examples/purchased-guides/resources.ts); [verification](validation-strategy.md#2026-09-10-entitlement-gating))

Orders/invoices is a second business-policy slice: authenticated tenant-local order numbers and invoice numbers, order lines, single-invoice issuance, payment transitions, checked integer totals, and explicit expected-version writes across three tables. Generated reads remain tenant-scoped; mutation RPCs use authored SQL and transactions. Live concurrent writes produced one commit and one `VersionConflict`; a failed invoice insert rolled back the order transition in regression coverage. This demonstrates the chosen billing rules, not accounting compliance, payment processing, inferred aggregate boundaries, or universal optimistic locking. ([Domain](../../examples/orders-invoices/domain.ts); [contracts](../../examples/orders-invoices/contracts.ts); [SQL](../../examples/orders-invoices/sqlite.ts); [verification](validation-strategy.md#2026-09-09-tenant-scoped-orders-and-invoices))

Repair workshops add a distinct read-model slice: a board of repairs joined to current customers and optional technicians, preserving booleans and missing-row nulls. The runnable handwritten baseline preceded the compiler; the final example removes its repeated storage projection and JOIN/alias SQL while preserving the native operation's behavior. This is evidence for flat joined projections and declared dependencies, not a staffing scheduler, a production authorization system, or general aggregate inference. ([Application](../../examples/repair-workshop/README.md); [board](../../examples/repair-workshop/board.ts); [verification](validation-strategy.md#2026-09-11-repair-workshop-joined-projections))

## Adjacent Native API Decisions

These are scoped integration decisions, not claims that unused APIs were validated:

- Use native `PersistedQueue` for durable handoff; use `DurableQueue` when completion must resume a workflow. The export example composes the latter over the former's SQL store, without another worker registry. ([Composition](../../examples/report-exports/runtime.ts))
- Use Entity only where identity-local serialization and scheduling are meaningful. `PrimaryKey`, `DeliverAt`, Singleton, and ClusterCron remain native and explicit; do not turn every Resource into an actor. ([Reminder protocol](../../examples/appointment-reminders/appointment-reminder-entity.ts); [background work](../../examples/appointment-reminders/background.ts))
- Keep RateLimiter at an explicitly chosen application boundary; do not infer durable business quotas or add a framework wrapper without a concrete requirement.
- Defer EventLog/EventJournal until an actual synchronization slice defines its semantics. They do not imply audit logging, event sourcing, or an outbox for existing resources.
- Defer Reactivity/AtomRpc until an interactive or read-model slice needs invalidation. Do not couple canonical domain schemas to client cache behavior.
- Multi-runner topology, execution-store version upgrades, cancellation policy, and external-effect idempotency/outbox design remain authored operational concerns. Separate execution and application databases are not an atomic transaction boundary. The completed example identity slice does not turn the workspace into a production IdP. ([Runtime contract](tables-and-queries.md#native-durable-execution); [example identity boundary](tables-and-queries.md#example-identity-boundary))

## Current Direction

Human direction on 2026-09-11 sequenced the remaining questions. These are next-slice choices, not evidence that the hypothesis is proven.

- Stay on SQLite. Next evidence is more business domains, not another database.
- Joins and multi-table query dependencies were the next declaration work. The repair-workshop slice now implements explicit flat projections and registered dependencies; it still infers no joins from foreign keys. Physical uniqueness, foreign keys, and indexes stay; cascade and richer relationship policy stay out until a slice needs them. ([Relational contract](tables-and-queries.md#relational-storage-declarations); [implemented projection boundary](tables-and-queries.md#declared-joined-projections))
- Where a canonical value has no lossless scalar representation, keep an explicit typed transform per field. Do not infer a JSON blob or other non-lossless encoding. This restates the derivation boundary. ([Thesis](thesis.md#derivation-boundary))
- The verified issuance/revocation slice is complete and now lives in the framework as `SqliteIdentity`: credentials are issued, expire, revoke, and resolve current account claims without placing identity in canonical resource schemas. Keep the portable subject-only authorization boundary; a production IdP or user-management lifecycle requires its own requirements and evidence. ([Identity runtime](../../packages/effect-domains/src/identity.ts); [SQLite identity](../../packages/effect-domains/src/sqlite-identity.ts))
- Expand mechanical storage support only when a slice cannot stay honest with the current scalar subset.
- Migration authoring changed once the hand-written histories measurably hurt: twenty artifacts carried every snapshot two or three times and ~30 identity column copies, so the v2 artifact drops the redundant `from`, references snapshots by name, and defaults identity copies. Steps, constants, and expressions remain explicit; there is still no planner, generator, or dialect work. The three `003_schema_string_checks` rebuilds stay as frozen history. ([Migration contract](tables-and-queries.md#sqlite-migrations-and-inspection))
- Guarded writes, status machines, and authored-operation plumbing are now derived where the repeated example code was mechanical: version guards, declared transitions, `UniqueViolation` translation, keyset list ranges/ordering, seeds, entitlement lookups, and operation contracts. Business rules stay authored inside those seams. The next domains should test whether these declarations generalize or start accreting options. ([Abstraction-pass validation](validation-strategy.md#2026-09-11-abstraction-pass))
- Do not invent a framework reconciliation policy for interruption or ambiguous commits until a failure slice actually hits them.

## Remaining Evidence

Still unproven after those choices:

- whether further SQLite domains actually generalize the conventions;
- whether the bounded joined-projection declaration generalizes beyond repair workshops without becoming a general query DSL;
- whether a production IdP or user-management lifecycle is required beyond the bounded example credential store;
- which encoded shape, if any, a future slice cannot avoid;
- whether declared `version`/`transitions`/`range`/`order` cover the next domains without growing into a query or workflow language (only billing and reservations exercise transitions; only the ledger and workshop exercise range/order);
- readability of large or database-specific v2 histories, when one hurts; and
- reconciliation of interruption and ambiguous commits, once a failure slice exists.

The table compiler directly interprets supported Effect AST nodes and rejects cyclic suspended scalar fields. Its storage semantics remain separate from canonical JSON RPC codecs; CLI support does not imply arbitrary schemas have lossless table representations. ([Table compiler](../../packages/effect-domains/src/table.ts); [table regressions](../../test/Table.test.ts); [CLI](../../packages/effect-domains/src/rpc-cli.ts))

## Success and Stop Conditions

The SQLite implementation removes exercised mechanical duplication, native execution examples avoid another workflow/actor language, and the identity slice establishes bounded example issuance/revocation without loading sessions into canonical schemas. Further architectural claims still require richer SQLite domain slices, joined projections beyond the demonstrated flat read model, and an explicit failure slice for interruption. Compare propagation, annotation cost, escape hatches, and clarity against the [validation criteria](validation-strategy.md) before generalizing these integrations. ([Refactoring direction](raw/refactoring-and-compatibility-direction.md); [Current direction](#current-direction))
