# Research Agenda

This page distinguishes the implemented API from evidence still needed to judge the project hypothesis. Mechanical, lossless derivation remains the boundary; business policy and semantic transformations remain authored. ([Project thesis](raw/project-thesis.md))

## Framework Direction

The intended product is conventionally generated application infrastructure for Effect: authors declare canonical schemas, select generated resource capabilities, and write commands and policies whose semantics are not in those schemas. Current evidence includes SQLite reservation policy, tenant-scoped orders/invoices, and two materially different native execution integrations: durable export/approval and scheduled per-recipient delivery. These bounded demonstrations do not establish general business-domain fit. ([Effect and declarative interface direction](raw/effect-and-declarative-interface-direction.md); [Verification limits](validation-strategy.md#evidence-boundary))

### Implemented contract

The 2026-09-10 radical simplification supersedes the earlier interfaces named in the dated evidence. Final validation for this revision is [pending](validation-strategy.md#2026-09-10-radical-simplification).

Supported fields compile to one product of physical metadata, codecs, and comparison evidence. A private creation-source language (`Input`, `Default`, `Generated`, `Subject`) drives create input and value evaluation; inspection renders the declared creation configuration. Closed resource operation descriptors drive repository/native RPC construction. The existing closed policy algebra retains private compiled authorization registration. These small internal languages do not introduce a universal framework, user-facing source DSL, or parallel transport DTO. ([Table](../../packages/effect-domains/src/table.ts); [Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts))

- `Resource.make({ name, schema, authorization, storage?, relations?, operations })` derives a storage table, policy-enforcing canonical repository, and only the RPC procedures selected by the single `operations` record. `Resource.crud` is the frozen `{ get: true, list: true, create: true, update: true, remove: true }` selection; `patch: true` selects patch. Omitted or `false` operations are not published, but all repository methods remain available locally. Authorization must explicitly select public, deny, or a typed resource policy. `storage` is a reversible representation with the same decoded fields as the canonical schema, so storage codecs do not leak onto the wire. ([Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts); [resource regressions](../../test/ResourceCrud.test.ts))
- `operations.create` is the only creation configuration: `defaults` fills only absent fields, `generated` accepts runtime `uuidV7` and `now` tokens through the `Value` service, and policy-authorized `fromSubject` maps canonical fields to typed `p.subject` operands. Generated and subject-bound fields are absent from create input and a supplied value is rejected; bindings cannot overlap defaults or generated fields. `operations.list` is the only list configuration: its declared equality filters and limit select list behavior; `true` selects bounded identifier-ascending pages with default limit 50. `operations: {}` publishes no resource RPC while retaining the local repository. ([Resource](../../packages/effect-domains/src/resource.ts); [Authorization](../../packages/effect-domains/src/authorization.ts); [Value](../../packages/effect-domains/src/value.ts))
- Declared list filters use compiled physical codecs. Every generated list, including local repository `list`, returns bounded `{ items, nextCursor }` and orders by identifier ascending only. There is no arbitrary order configuration, separate repository `page`, or unbounded generated array list. Published patch input is `{ key, changes }`; the local repository remains `patch(key, changes)`. Identifier changes are rejected and the complete resulting value is validated transactionally. ([Resource](../../packages/effect-domains/src/resource.ts); [resource regressions](../../test/ResourceCrud.test.ts))
- Authorization scope is mandatory and conjoined with action rules. Hidden rows look missing; SQL filters before pagination; mutations check current/candidate state and readable results transactionally. A closed policy fold drives evaluation, SQL, references, and inspection. SQL visibility accepts native Boolean values through SQLite `0`/`1`, but rejects semantic Boolean codecs. Protected RPCs require request-local subjects through `AuthorizationRpc.Authenticator`; authored SQL remains privileged. ([Authorization contract](tables-and-queries.md#resource-authorization); [SQL interpreter](../../packages/effect-domains/src/policy-sql.ts); [authorization regressions](../../test/Authorization.test.ts); [RPC identity regressions](../../test/AuthorizationRpc.test.ts))
- Native `Rpc.make` and `RpcGroup.make` define operation contracts; `Schema.toCodecJson` supplies explicit JSON representations where needed. `RpcGroup.toLayer` installs authored handlers, and `Application.make({ name, parts })` accepts Resources, native `{ group, handlers }` bundles, and nested Applications. Nested resources flatten; duplicate table names and RPC operation names are rejected. The former `Commands` module and package export are removed, not aliased. ([Reservation contracts](../../apps/reservations/contracts.ts); [billing composition](../../apps/orders-invoices/application.ts); [Application](../../packages/effect-domains/src/application.ts))
- Authored `Effect.catchTags` translates selected failures after transaction unwind. Native RPC provides middleware dispatch and invocation scopes; adapter regressions preserve request-local identity, handler codec services, and finalization after success/failure within one MCP session. Wrapper-specific direct-call and optional-mapper contracts are retired. ([Reservation handlers](../../apps/reservations/sqlite.ts); [billing handlers](../../apps/orders-invoices/sqlite.ts); [MCP regressions](../../test/RpcMcp.test.ts); [removal evidence](validation-strategy.md#2026-09-09-command-wrapper-removal))
- `ApplicationBun.run(application, { database, services?, initialize?, background?, routes?, admin? })` returns the Bun entrypoint `Effect` for native `BunRuntime.runMain`. Database history remains explicit. Startup prepares application storage, builds application services, initializes, registers background layers, and launches HTTP or a worker lifetime. Native execution services compose in the authored `services` layer; there is no `execution` option or framework filename-isolation policy. `worker` exists only with `background`; native HTTP `routes` run only under `serve`. The runner never builds browser assets. ([Bun runtime](../../packages/effect-domains/src/application-bun.ts); [native execution contract](tables-and-queries.md#native-durable-execution))
- `serve` derives a Streamable HTTP MCP endpoint at `/mcp` from the application RPC group and can opt into browser admin with `admin: true` or `{ path?, presentation?, allowedOrigins? }`, defaulting to `/admin`. The private Bun workspace builds [`apps/admin`](../../apps/admin/) explicitly with `bun install` then `bun run build`; the runtime loads only its prebuilt `dist/client.js` and `dist/style.css`. MCP and admin both call the same native in-process RPC transport, so handlers, middleware, service codecs, and request bearer authentication remain authoritative per call; no token is persisted. Admin generates forms, resource lists, filters, cursor navigation, and a JSON fallback from inspection. Presentation is display-only configuration; it neither changes canonical metadata nor infers permission. Browser calls must be same-origin. Loopback is trusted by default; a non-loopback host must explicitly configure exact `allowedOrigins`, which does not grant CORS. ([Browser client](../../apps/admin/src/client.ts); [Browser stylesheet](../../apps/admin/src/style.css); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts))
- In-process RPC defects are request-local. Admin/MCP codecs use captured handler services, while authentication remains request-local. No-payload CLI input is schema-derived rather than assumed to be an empty object. ([Transport](../../packages/effect-domains/src/rpc-in-process.ts); [CLI regressions](../../test/RpcCli.test.ts); [adapter regressions](../../test/ApplicationAdmin.test.ts))
- `SqliteMigrations.make({ id, from, to, steps })` constructs an explicit artifact; `initial({ id, tables })` derives fresh table/index creation. `snapshot`, `decodeHistory(raw)`, and `load(manifest)` retain frozen snapshots and ordered history. Schema constructors under `SqliteMigrations.steps` and `SqliteMigrations.copies` express authored changes directly. There is no `plan`, `generate`, migration intent DSL, or schema CLI. Every nonempty managed schema requires an initial migration. The applied-artifact ledger remains the sole state, and exact drift, foreign-key, and transactional replay verification remain mandatory. Existing artifact JSON histories are not rewritten. ([Migrations](../../packages/effect-domains/src/sqlite-migrations.ts); [migration contract](tables-and-queries.md#sqlite-migrations-and-inspection); [authoring guide](../../apps/README.md#review-schema-changes))
- `inspect` emits generated operation input/output/error schemas and resource canonical schema, creation/list policy, including rendered `fromSubject` mappings, storage schema, and the physical table as JSON-encoded `Table.snapshot`; it does not maintain a duplicate physical DTO. Physical field generation uses the native `generation` key, not `generated`. It provides the descriptive input for admin generation, while presentation stays external. There is no opaque runtime placeholder: handler services and transaction boundaries remain deliberately uninspectable rather than invented metadata. ([Inspection](../../packages/effect-domains/src/application-inspect.ts); [Table](../../packages/effect-domains/src/table.ts); [Admin adapter](../../packages/effect-domains/src/application-admin.ts))
- Native workflow/entity proxy bundles compose directly in `Application.parts`; native registration and queue-worker layers compose in `background`. Applications supply private execution SQL with `Layer.provide` when composing native execution layers into `services`, without exporting that SQL as application SQL. The shared example helper checks opened database paths/inodes before native execution tables initialize; it does not promise pre-open URL or dangling-symlink rejection. Application Entity/Cron work captures its application database connection before native Sharding supplies its invocation context. The workflow application owns its diagnostic schemas and reads native `Sharding` and `RunnerStorage` services directly. ([Workflow runtime](../../apps/durable-workflows/runtime.ts); [reminder registration](../../apps/durable-reminders/background.ts); [diagnostics](../../apps/durable-workflows/workflow.ts))

Publication and runtime configuration remain outside canonical schemas. Intrinsic identity is domain metadata; generated persistence identity is an adapter concern. Native RPC declarations belong to the operation-contract layer and do not select HTTP transport; applications compose parts and may opt into administration without adding UI metadata to domain schemas. The clean cutover leaves no legacy top-level resource `create`/`list`, command-service representation, or compatibility adapter. ([Domain identifier direction](raw/domain-identifier-and-basic-persistence-direction.md); [Application](../../packages/effect-domains/src/application.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts))

## Established Persistence Findings

`Table.make` compiles supported flat canonical fields to reversible storage codecs and SQLite fields. An explicit `identifier` remains the key; otherwise persistence adds UUIDv7 `id` to the row representation. The compiler supports string, numeric, boolean, nullable scalar, and timestamp representations, not arbitrary nested or optional-key models. ([Table](../../packages/effect-domains/src/table.ts); [table regressions](../../test/Table.test.ts))

Compiled column codecs preserve suspended scalar mappings and exact-filter semantics; nullable physical identifiers are rejected. Canonical JavaScript string-length checks are not SQLite constraints. Explicit example rebuilds remove old misderived constraints without reinterpreting frozen history, and interacting renames copy original source values. ([Persistence contract](tables-and-queries.md#canonical-and-storage-representations); [migration contract](tables-and-queries.md#sqlite-migrations-and-inspection))

Table/Resource `relations` now declares named composite uniqueness, foreign keys, and ordinary secondary indexes outside canonical schemas. Complete-graph validation checks physical targets; SQLite enables foreign keys and migration history manages constraint rebuilds and explicit index steps. No join or cascade policy is inferred. ([Relational contract](tables-and-queries.md#relational-storage-declarations); [migration regressions](../../test/RelationalMigrations.test.ts))

Generated repositories handle routine persistence; authored operations use native Effect `SqlSchema` and `SqlClient`, or explicit schema conversions. There is no framework `Query` descriptor or persistent-reference cache. Transactions, caching, invalidation, and concurrency policy remain explicit application concerns. ([Authored SQL](../../apps/authored-sql/sqlite.ts); [transactional reservation policy](../../apps/reservations/sqlite.ts))

## Application Evidence

The reservation application uses canonical stock and reservation schemas with generated reads and explicit transactional reserve, confirm, release, accounting, and transition policy. Five supporting applications exercise minimal generated book CRUD, configured todo CRUD, authored book queries, service-dependent storage codecs, and a historical document migration. Basic CRUD and authored SQL share the canonical book schema; custom errors and remove results remain in the authored example. These are integration demonstrations, not a second materially different business-policy slice. ([Basic resource](../../apps/basic-crud/resources.ts); [Authored contracts](../../apps/authored-sql/contracts.ts); [Reservation policy](../../apps/reservations/sqlite.ts); [Example guide](../../apps/README.md))

Two supporting applications now expose distinct authored authorization policies without new framework machinery: tenant-owned todos restrict edits by current completion state and preserve ownership; global shared notes use role membership while retaining their semantic storage codec. A shared example authenticator resolves deliberately public bearer sessions to server-owned claims. This is runnable policy evidence, not a production identity system or a second materially different business-policy slice. ([Todo rules](../../apps/resource-crud/resources.ts); [Note rules](../../apps/service-codec/resources.ts); [Demo identities](../../packages/example-support/src/authentication.ts))

The seven resource-focused examples select `admin: true`; the two durable examples expose RPC/CLI/MCP without admin. The service-codec example's `StoredNoteSchema` uses native `mapFields(Struct.assign(...))` to replace only the storage `text` field. ([Example entrypoints](../../apps/); [Stored note codec](../../apps/service-codec/storage.ts))

The dated [authorized-example verification](validation-strategy.md#2026-09-09-authorized-examples) and [authorization verification](validation-strategy.md#2026-09-08-resource-authorization) remain historical evidence for their exercised policy, codec, migration, identity-isolation, SQL-parity, and type-boundary interfaces. They are not a claim that later implementation changes have been validated.

The durable workflow composes approval, durable timing, an activity, and queue-backed artifact creation. The reminder integration instead composes persisted per-recipient scheduling, idempotent application receipts, a singleton projection, and cron retention. Forced restarts and worker-only recovery were exercised for both; proxy authorization and protected workflow diagnostics were checked through actual transports. These demonstrate native composition without a framework jobs/actor DSL, not production identity or multi-runner deployment. ([Durable verification](validation-strategy.md#2026-09-09-native-durable-execution); [application runbooks](../../apps/README.md#durable-workflows))

Orders/invoices is a second business-policy slice: authenticated tenant-local order numbers and invoice numbers, order lines, single-invoice issuance, payment transitions, checked integer totals, and explicit expected-version writes across three tables. Generated reads remain tenant-scoped; mutation RPCs use authored SQL and transactions. Live concurrent writes produced one commit and one `VersionConflict`; a failed invoice insert rolled back the order transition in regression coverage. This demonstrates the chosen billing rules, not accounting compliance, payment processing, inferred aggregate boundaries, or universal optimistic locking. ([Domain](../../apps/orders-invoices/domain.ts); [contracts](../../apps/orders-invoices/contracts.ts); [SQL](../../apps/orders-invoices/sqlite.ts); [verification](validation-strategy.md#2026-09-09-tenant-scoped-orders-and-invoices))

## Adjacent Native API Decisions

These are scoped integration decisions, not claims that unused APIs were validated:

- Use native `PersistedQueue` for durable handoff; use `DurableQueue` when completion must resume a workflow. The export example composes the latter over the former's SQL store, without another worker registry. ([Composition](../../apps/durable-workflows/runtime.ts))
- Use Entity only where identity-local serialization and scheduling are meaningful. `PrimaryKey`, `DeliverAt`, Singleton, and ClusterCron remain native and explicit; do not turn every Resource into an actor. ([Reminder protocol](../../apps/durable-reminders/reminder-entity.ts); [background work](../../apps/durable-reminders/background.ts))
- Keep RateLimiter at an explicitly chosen application boundary; do not infer durable business quotas or add a framework wrapper without a concrete requirement.
- Defer EventLog/EventJournal until an actual synchronization slice defines its semantics. They do not imply audit logging, event sourcing, or an outbox for existing resources.
- Defer Reactivity/AtomRpc until an interactive or read-model slice needs invalidation. Do not couple canonical domain schemas to client cache behavior.
- Multi-runner topology, execution-store version upgrades, production identity, cancellation policy, and external-effect idempotency/outbox design remain authored operational concerns. Separate execution and application databases are not an atomic transaction boundary. ([Runtime contract](tables-and-queries.md#native-durable-execution))

## Remaining Questions

Further evidence must determine:

- whether these conventions generalize beyond SQLite and the demonstrated business domains;
- whether joins, multi-table query dependencies, or richer relationship policies earn declarations beyond the implemented physical constraints;
- how explicit storage transformations compose where a canonical value has no lossless scalar representation;
- how verified identity issuance and revocation compose with the demonstrated authenticated multi-resource commands in production;
- which encoded shapes earn mechanical storage or CLI support;
- whether explicit migration steps remain readable for larger histories and database-specific changes; and
- how interruption and ambiguous database outcomes should be reconciled.

The table compiler directly interprets supported Effect AST nodes and rejects cyclic suspended scalar fields. Its storage semantics remain separate from CLI flag interpretation; neither implies arbitrary schemas have lossless table representations. ([Table compiler](../../packages/effect-domains/src/table.ts); [table regressions](../../test/Table.test.ts); [CLI](../../packages/effect-domains/src/rpc-cli.ts))

## Success and Stop Conditions

The SQLite implementation removes exercised mechanical duplication, and the native execution examples avoid introducing another workflow/actor language. Further architectural claims still require richer domain slices and explicit distributed failure scenarios. Compare propagation, annotation cost, escape hatches, and clarity against the [validation criteria](validation-strategy.md) before generalizing these integrations.
