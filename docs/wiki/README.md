# Effect Domains Wiki

This directory is the persistent, source-grounded wiki for the Effect Domains design hypothesis and implementation workspace.

Effect Domains derives routine application machinery from canonical Effect Schemas while leaving semantic storage transformations, business policy, and migration intent explicit. The maintained [framework contract](research-agenda.md#implemented-contract) records the current API; the [validation record](validation-strategy.md#verification-record) separates exercised behavior from historical and unproven claims. The implementation is a private Bun workspace: the framework is [`packages/effect-domains`](../../packages/effect-domains/), shared fixtures are [`packages/example-support`](../../packages/example-support/), runnable examples are under [`examples`](../../examples/), and the browser admin is separately prebuilt in [`apps/admin`](../../apps/admin/).

## Current Status

The 2026-09-12 client and operation consolidation moved repeated mechanics behind framework boundaries without deriving application policy. `Resource.published` now carries exact generated capabilities; `ResourceEditor` rejects resources missing public CRUD operations. `ResourcePager` composes page continuation with keyed request ownership and is exercised by the derived editor, reading list, and authenticated field notes. `RpcBrowser`, `BrowserRuntime`, `IdentitySession`, and `StaticSpa` replace example-local transport, startup, session-command, and asset-route plumbing across all twelve applications; example-web retains presentation and build support only. `Operation.family` binds shared names/policy/transaction/unavailable boundaries, while `SqliteView.listOperation` publishes a derived read model without manual field forwarding. Business errors, filters, mutation refresh, authorization, transaction selection, and visual presentation remain explicit. ([Verification](validation-strategy.md#2026-09-12-client-and-operation-boundaries); [contract](research-agenda.md#implemented-contract))

The 2026-09-11 [abstraction pass](validation-strategy.md#2026-09-11-abstraction-pass) derived the machinery the twelve applications had been repeating by hand: `version` guards and `VersionConflict`, declared `Transitions` with status-guarded writes and derived errors, `UniqueViolation` from declared unique tuples, keyset list `range`/`order`, implicit null defaults, `repository.ensure`, `Operation.make`/`bundle` for authored operations, `Entitlements.fromTables`, `Table.project`, derived relation names and scoped foreign keys, framework `SqliteIdentity` over a private client, v2 migration artifacts (2,665 JSON lines from 4,938), and shared domain value schemas. Billing's authored SQL fell from 498 to 266 lines while its business rules stayed authored. Final workspace check, zero lint findings, all 120 tests, and live billing/reservation/ledger CLI plus admin scenarios passed; the framework grew to 7,193 lines, a cost the record states. A same-day follow-up made undeclared domain failures in `Operation.make` a compile error, published a generic transition surface in the repair workshop and verified it through admin and MCP, fixed the blocking report generation call, and confirmed the v2 ledger failure message. See the [implemented contract](research-agenda.md#implemented-contract).

On 2026-09-11 the remaining research questions were sequenced: stay SQLite with more domains; declare joins and query dependencies; keep explicit per-field storage transforms; implement verified identity issuance and revocation; add encoded shapes only when a slice cannot avoid them; defer migration-authoring changes until a history hurts; prove interruption with a failure slice. The identity slice is now complete as a bounded example credential store, while production IdP work remains outside the claim. See [current direction](research-agenda.md#current-direction).

The [repair-workshop slice](../../examples/repair-workshop/README.md) supplies the first join/dependency evidence from that direction. `SqliteView` removes repeated storage codecs and SQL aliases/joins; `SqliteView.list` derives its bounded typed filter/range payload, shared Page result, keyset cursor handler, and dependency declaration. The board uses that derived contract while authorization and transaction policy remain explicit. ([Current contract](tables-and-queries.md#declared-joined-projections); [bounded regression](../../test/SqliteView.test.ts))

The [support-case slice](../../examples/support-cases/README.md) is the thirteenth application, third versioned business-policy slice, and second joined-board consumer. It reuses `Resource`, `Transitions`, `Operation.family`, `SqliteView`, `Table.project`, and imported migration history without framework changes. Case/event writes are transactional; assignment policy and nested history SQL remain authored. Live CLI and browser checks exercised open, triage, assignment, resolution, reopen, joined reads, and event history, while a database-trigger regression proved rollback when event insertion failed. This does not establish process-interruption reconciliation, richer join derivation, or a general aggregate mapper. ([Verification](validation-strategy.md#2026-09-13-support-case-sqlite-vertical-slice))

Automatic [RPC telemetry](../reference/runtime.md#opentelemetry-tracing) now installs native Effect OTLP tracing across Bun command lifetimes when an endpoint is configured. The current identity/browser cutover keeps portable schemas and `IdentityRuntime` separate from the native identity RPC group and handlers. Example clients use existing native RPC groups rather than handwritten browser envelopes; their request ownership and in-memory session helpers discard stale replies and keep credentials out of browser storage. The separate SQLite credential store issues expiring, revocable opaque credentials while checking current account state, but does not claim production IdP capability. [Current evidence](validation-strategy.md#2026-09-11-native-identity-and-browser-client-cutover) records the exercised boundaries.

The public editorial-calendar page now exercises the first contract-derived Foldkit resource editor. `ResourceEditor.make` owns its generated CRUD client service, model/messages/commands, cursor state, reversible form conversion, stale-result rejection, and reload-after-mutation mechanics. Save completion is isolated from newer edits: successful saves still refresh the list without replacing a superseding form or selection, and stale failures cannot publish field errors into that form. The page still authors its field codecs, copy, error formatting, and complete presentation. Shared form codecs and request ownership moved from example support into `effect-domains`; authenticated, filtered, and non-CRUD pages remain explicit rather than being forced through the editor. ([Current contract](research-agenda.md#implemented-contract); [browser boundary](tables-and-queries.md#commands-applications-and-admin); [verification](validation-strategy.md#2026-09-12-resource-editor-save-ownership); [editorial client](../../examples/editorial-calendar/web/main.ts))

`ResourceEditor` also enforces one pending command per mutation kind: repeated save or remove messages cannot enqueue duplicate RPC effects while the accepted request remains pending. This is client command ownership rather than server-side idempotency. [Current evidence](validation-strategy.md#2026-09-12-resource-editor-pending-mutation-suppression) records the failing pre-fix reducer case and focused checks.

`Resource.make({ name, schema, authorization, operations, storage?, relations?, version?, transitions? })` retains declarative CRUD, optional patch and transition publication, explicit authorization, creation defaults, generation, typed subject bindings, and implicit null defaults. Every generated `list` returns the shared bounded `Page` contract; concrete generated RPC descriptors are public under `resource.contracts`. Transition authorization is its own current/candidate action. Foreign keys use typed `Table.reference` targets whose exact descriptor identity is checked at application composition. ([Resource](../../packages/effect-domains/src/resource.ts); [Page](../../packages/effect-domains/src/page.ts); [Table](../../packages/effect-domains/src/table.ts); [current contract](tables-and-queries.md))

Native execution layers compose through application-owned `services`; `SqliteBunRuntime.privateClient({ application, purpose })` opens identity or execution stores that provably differ from the application database. ([Operation](../../packages/effect-domains/src/operation.ts); [Application](../../packages/effect-domains/src/application.ts); [Bun runtime](../../packages/effect-domains/src/application-bun.ts); [native composition](tables-and-queries.md#native-durable-execution))

## Development

Run these commands from the private workspace root. The explicit build precompiles the optional browser admin; runtime only loads its output:

```bash
bun install
bun run build
```

The root checks include all workspace packages and the root integration suite:

```bash
bun run check
bun run lint
bun run test
```
